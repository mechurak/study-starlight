# 검증

사이트 콘텐츠·코드·설정 변경은 작업을 묶어 마친 뒤 다음 명령을 한 번 실행한다.

```bash
pnpm check
```

`check:content`가 `_deck.mjs`와 MDX에서 파생한 slug·순서·그룹, `category`·`tag` 어휘,
필수 baseline, 프론트매터, h4, 미지원 펜스 언어(promql·logql·traceql → `text`), 덱 index
컴포넌트, `<Thesis>` 이관 표시, 필수 `<TermIntro>`, 검토 날짜 정합성을 검사한다. 이어서 Astro
빌드와 Pagefind 인덱스를 만들고, `check:links`가 **렌더된 HTML의 내부 페이지·파일·anchor**를 검사한다.
외부 URL의 생존 여부는 네트워크 상태와 rate limit 영향을 받으므로 기본 검사를 막지 않는다.

`AGENTS.md`·`README.md`·`docs/`·`_baseline.md`처럼 빌드에 포함되지 않는 지침·계획 문서만
바꿨다면 `git diff --check`, 수정 diff, 변경한 참조 경로만 확인한다. 빌드·브라우저는 실행하지 않는다.
이미 통과한 검사는 그 결과에 영향을 주는 새 변경이나 실패가 없으면 반복하지 않는다.

덱별 검토 이력·검토 주기 초과·`legacyThesis` 잔량은 필요할 때 다음으로 본다.

```bash
pnpm report:content
```

## 변경별 최소 검증

**`playwright-cli` 등 브라우저 검증은 기본 절차가 아니다.** 자동 검사·소스·정적 산출물로
판단할 수 없는 화면 동작이나 레이아웃 문제가 있을 때만 사용한다. 시작 전에 확인할 문제와
대표 페이지 1~2개를 정하고, 그 문제가 해결되면 끝낸다. 페이지 수가 늘었다는 이유로 덱 전체를
순회하거나 모바일·테마·확대·검색 검사를 일괄 실행하지 않는다.

| 변경 | 검증 |
|---|---|
| 빌드에 포함되지 않는 지침·계획 문서만 변경 | diff·변경한 참조 경로 확인 |
| 문장·문단·링크 | `pnpm check`로 마침 |
| 새 페이지·분할·이름·덱 메타데이터·순서 변경 | `pnpm check` + 소스의 그룹·순서·map 확인으로 마침 |
| 일반 표·기존 컴포넌트 사용·기존 이미지 이동 | `pnpm check`로 마침. 구체적인 넘침·표시 우려가 있을 때만 해당 부분 확인 |
| 새 이미지·D2 추가·배치 변경 | `pnpm check` + 변경한 이미지의 정적 렌더 확인. 브라우저 동작은 바꾸거나 문제가 있을 때만 확인 |
| 테마·레이아웃 CSS·UI override·새 인터랙션·클라이언트 리다이렉트 | `pnpm check` + 영향을 받는 동작만 대표 페이지에서 브라우저 확인 |
| 화면 동작에 영향 없는 config 변경 | `pnpm check`로 마침 |

브라우저가 필요한 경우에만 `pnpm preview`를 사용한다. 자동화 도구는 선택 사항이며,
같은 결과를 이미 직접 확인했다면 `playwright-cli`로 다시 확인하지 않는다.

D2의 전체 작성 규칙은 [d2-authoring.md](d2-authoring.md)에 있다. 폭·배치를 조정하는 반복 작업에서는 매번 빌드하지 말고
`node scripts/d2-measure.mjs [--png] <파일.mdx>`를 쓴다 — 빌드 산출물과 픽셀 단위로 같은
크기를 캐시 준비 뒤 파일당 1~2초에 찍고, `--png`는 블록별 이미지를 `.d2-measure/`에 만들어 렌더 결과
(라벨 겹침·컨테이너 관통처럼 폭 수치로 안 잡히는 결함)를 빌드·브라우저 없이 훑게 해 준다.
이 스크립트도 `astro.config.mjs`와 같은 준비 함수를 거쳐 캐시된 native D2 v0.8.2 CLI를 쓴다.
정적 렌더 확인으로 판단이 끝나면 `pnpm check`로 마친다. 브라우저 확인을 자동으로 추가하지 않는다.

## 브라우저가 필요할 때 고를 항목

아래는 전체 실행 목록이 아니다. 변경한 동작에 해당하는 항목만 골라 확인한다.

1. D2·이미지 표시 동작을 바꿨다면: SVG 로드·테마 전환·확대 dialog·애니메이션 중 바꾼 동작을 확인한다.
2. 사이드바·DeckMap UI를 바꿨다면: 대표 덱에서 현재 항목·접기·이동 중 바꾼 동작을 확인한다.
3. 검색 UI·색인 설정을 바꿨다면: 검색 dialog에서 관련 한국어 질의·덱 별칭으로 결과를 확인한다.
4. 반응형 배치를 바꿨거나 넘침이 의심된다면: 390px에서 문서 본문이 `scrollWidth > clientWidth`가 아닌지 확인한다.
   코드 블록 자체의 가로 스크롤은 정상이다. 랜딩의 태그 칩 바는 여기서 5줄까지 늘어난다.
5. 랜딩 태그 필터·정렬 동작을 바꿨다면: 칩을 눌렀을 때 카드 보기에서 섹션이
   헤딩째 사라지는지, 테이블 보기로 바꿔도 필터가 유지되는지, 정렬 → 필터와
   필터 → 정렬 두 순서 모두 되는지 확인한다. 0이 되는 칩은 흐려지고 눌리지 않아야 하며,
   선택된 칩은 흐려지지 않아 되돌아 나올 수 있어야 한다. `?tags=k8s,onprem` 링크를
   새 탭에서 열면 칩이 눌린 채로 뜨고, 모르는 id는 조용히 버려져야 한다.
   빈 상태는 크래프트한 URL(`?tags=onprem,frontend`)로만 닿는다.
6. 랜딩 검색 제외 영역을 바꿨다면: 필터 바·툴바·태그 칩·테이블 보기·빈 상태는 `data-pagefind-ignore` 대상이다.
   "온프렘"으로 검색했을 때 랜딩(`/`)이 결과에 뜨면 어딘가 빠진 것이다.

Playwright 같은 브라우저 자동화를 썼다면 검증 후 `git status --short`로 임시 로그·스냅샷이
변경 목록에 남지 않았는지 확인한다. 이 저장소에서 `.playwright-cli/`는 검증 산출물이므로
커밋하지 않고 `.gitignore`로 제외한다.

`<Tabs>` 안을 확인해야 한다면 해당 탭을 선택한다. 모든 비활성 패널을 강제로 열어 전체를 검사하지 않는다.

## 산출물에서만 잡히는 CommonMark 문제

강조 기호가 그대로 남았는지 확인할 때:

```bash
grep -rho '\*\*[^<*]\{0,45\}' dist --include=index.html | sort -u
```

의도하지 않은 취소선이 생겼는지 확인할 때:

```bash
grep -rho '<del>[^<]*</del>' dist --include=index.html | sort -u
```

코드 블록의 `/**`, 문법을 설명하는 예제, 의도적으로 쓴 `~~취소선~~`은 정상이다.
