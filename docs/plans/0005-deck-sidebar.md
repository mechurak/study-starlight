실행 범위: 전체 구현·이관·검증. 커밋·푸시·배포는 포함하지 않는다.

[계획 관리 규칙](README.md)을 따른다.

## 범위와 입력

정본은 `src/data/load-decks.mjs`, `deck-schema.mjs`, `src/content.config.ts`,
`scripts/check-content.mjs`, 각 덱의 `_deck.mjs`·MDX와 `_baseline.md`다.
공통 작성·검증·Starlight 변경 지침을 따른다. 각 덱의 baseline은 이관 전에 읽었다.
이전 요청에서 수정한 검토 이력 표시와 관련 문서를 보존한다.

페이지 이름은 확장자를 뺀 덱 상대 파일 경로다. `index.mdx`는 자동으로 맨 앞에 두며
목록에는 적지 않는다. 빈 그룹은 허용하지 않는다. 제목·본문·검토 날짜는 구조 이관만으로 바꾸지 않는다.

## 실행 기록

- 이관 전 26개 덱의 topics·랜딩·slug·427개 본문을 임시 파일에 저장했다.
- 실제 sidebar UI는 변경하지 않는다. 구조 데이터의 동등성과 생성 HTML로 검증하고 브라우저는 띄우지 않는다.
- 26개 덱의 topics·랜딩 데이터와 453개 URL 집합이 이전과 동일하다. 427개 본문 이관 직후
  나머지 frontmatter와 본문이 보존됐음을 비교했다. 이후 Starlight 덱의 관련 설명·예제만 고쳤다.
- `deck-sidebar.test.mjs`의 6개 검사로 배열 순서·하위 경로와 중복·누락·없는 파일·index 직접 등록·
  빈 그룹·잘못된 경로 거부를 확인했다. `check:content`에 포함했다.
- 의미 리뷰: 구조 설명은 제목·설명과 목차의 소유 위치를 구분한다. 첫 덱 예제는 4개 파일의 최소
  등록 뒤 둘째 페이지를 임시로 복사해 순서 변화·URL 보존·복구를 관찰하도록 갱신했다.
  `structure`의 옛 프론트매터 절 anchor는 빈 span으로 보존했다. 기존 완료 계획은 과거 기록으로 유지했다.

## 완료 기록

- 2026-09-19: 26개 덱을 이관하고 본문 427개의 구조 필드를 제거했다. Starlight 설명을 제외한
  413개 본문과 그 밖의 frontmatter 값은 원본과 동일하다. URL·topic 목차·랜딩 데이터도 보존됐다.
- 첫 덱 문서의 코드 블록 4개를 실제 임시 덱으로 만들어 콘텐츠 검사·자동 index 등록을 확인했다.
  둘째 페이지 추가·목록 순서 뒤집기·원복과 옛 frontmatter 필드 두 종류의 거부도 확인한 뒤 임시 덱을 제거했다.
  예제 덱의 전체 HTML 빌드는 별도로 하지 않았으며, 최종 사이트 검사는 임시 덱을 제거한 상태에서 수행했다.
- `npm run check` 통과: 목차 테스트 6개, 26개 덱·454개 MDX 콘텐츠 검사, 513개 페이지 빌드,
  40,195개 내부 페이지·anchor 링크 검사. `git diff --check`도 통과했다.
- 대표 생성 HTML 2개(`cka-udemy/basics`, `starlight/structure`)에서 그룹 이름·링크 순서가
  이관 전 목차와 동일하고, Starlight의 기존 프론트매터 절 anchor가 남아 있음을 확인했다.
- 작성 지침·README·AGENTS·관련 baseline과 Starlight 학습 예제를 새 구조로 갱신했다.
  `decks.mjs`는 re-export를 그대로 두고 소유 위치를 설명하는 주석만 맞췄다.
- 커밋·푸시·배포는 실행하지 않았다. 이번 변경은 MDX frontmatter를 바꾸므로 커밋하면
  Git 이력 기반 랜딩 수정일도 모든 덱에서 갱신된다.
