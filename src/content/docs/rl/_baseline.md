# rl 덱의 기준

`rl` 덱을 고치기 전에 읽는다. 다른 덱에는 해당하지 않는다.

## 이 덱의 축

**축 1 — 강화학습을 쓸지 말지 먼저 판정한다.** 이 덱은 "RL은 좋은 것"이라고 쓰지 않는다.
지도학습·규칙·최적화로 되는 일에 RL을 얹으면 비용만 100배가 된다는 것이 1장의 결론이고,
그 판정 기준(**순차적 결정 · 지연 보상 · 내 행동이 다음 상태를 바꾼다**)이 덱 전체에서 반복된다.

**축 2 — 시뮬레이터의 유무가 두 응용을 가른다.** 이 덱이 트레이딩과 로봇을 한 덱에 묶은 이유다.

| | 로봇 (14~16장) | 트레이딩 (11~13장) |
|---|---|---|
| 시뮬레이터 | **만들 수 있다** — 물리 법칙이 안 변한다 | **못 만든다** — 내 주문이 시장을 바꾼다 |
| 그래서 | 수십억 스텝을 찍어 내고 on-policy(PPO)로 민다 | 로그 데이터로 배우는 **오프라인 RL**과 보수적 검증 |
| 진짜 문제 | **sim-to-real 격차** | **비정상성과 과최적화** |

**한쪽 장을 고치면 이 대비가 유지되는지 확인한다** — 두 응용을 나란히 두는 것이 이 덱의 값이다.

**축 3 — 보상이 문제의 8할이다.** 알고리즘 선택(4~7장)보다 보상 설계(8장)와 평가(10장)에서
결과가 갈린다. 각 응용 장은 반드시 **상태 · 행동 · 보상을 무엇으로 놓았는가**를 표로 밝힌다.

## 범위 경계

- **알고리즘은 오늘 실제로 쓰는 것만 판다** — DQN 계열 · PPO · SAC · 오프라인 RL(CQL/IQL).
  A3C · TRPO · Rainbow의 개별 트릭 같은 것은 **표에 이름과 "언제 필요한가"만** 남긴다.
- **수학은 직관까지만.** 증명·수렴 정리는 쓰지 않는다. 벨만 방정식과 정책 경사 정리는
  "무엇을 말하는 식인가"를 한국어 문장으로 풀고, 식 자체는 아래 표기 규칙대로 적는다.
- **금융 지식과 로봇 제어 이론 자체는 이 덱의 범위가 아니다.** 옵션 가격결정도, 역기구학도
  설명하지 않는다 — RL과 맞닿는 자리에서 필요한 만큼만 준다.
- LLM 쪽 RL(RLHF · GRPO · 검증 가능한 보상)은 **17장 진로 편에서 직무 지형으로만** 다룬다.
  이 덱의 응용 두 축이 아니다. 이 주제로 장을 늘리게 되면 별도 덱으로 뽑는다.

## 표기 규칙 — 수식

**이 사이트에는 KaTeX·MathJax가 없다**(remark-math를 안 쓴다). LaTeX를 쓰면 그대로 글자로 나온다.
수식은 둘 중 하나로 적는다 —

- 인라인은 백틱: `` `Q(s,a)` ``, `` `γ = 0.99` ``
- 여러 줄은 ` ```text ` 코드 블록. 기호는 유니코드로 (`α` `γ` `π` `∇` `𝔼` 대신 `E[...]`)

```text
Q(s,a) ← Q(s,a) + α · [ r + γ · max_a' Q(s',a') − Q(s,a) ]
                        └────── TD 타깃 ──────┘
```

**식을 넣을 때는 바로 아래에 "이 식이 하는 말" 한국어 한 문장을 반드시 붙인다.**
식만 있고 해설이 없는 자리는 이 덱에서 버그로 취급한다.

## 서술 규칙

각 장 첫머리의 `<TermIntro>` 상자가 의무다 — 규칙은 AGENTS.md "덱" 절.

- **알고리즘 장(4~7)은 네 단계 순서를 지킨다** — ① 앞 장에서 뭐가 안 됐나 → ② 아이디어 한 문장
  → ③ 실제 동작(의사코드·그림) → ④ 언제 쓰고 언제 안 쓰나. **③부터 시작하지 않는다.**
- **응용 장(11~16)은 같은 틀로 쓴다** — ① 이 도메인을 MDP로 어떻게 놓나(상태·행동·보상 표)
  → ② 여기서만 생기는 함정 → ③ 실제로 쓰이는 자리와 안 쓰이는 자리 → ④ 도구.
- **"논문에서는 된다"와 "현장에서 쓴다"를 반드시 구분한다.** 특히 주가 예측 RL은
  블로그·논문이 압도적으로 많고 실전 채택은 좁다 — 이 대비를 흐리면 이 덱은 값을 못 한다.
  성과를 인용할 때는 **어디서·무슨 조건에서**를 같이 적는다.
- **환경 코드는 Gymnasium API 하나로 통일한다** (`reset()` → `step()` → `terminated`/`truncated`).
  옛 `gym` API(`done` 하나로 끝나던 것)로 쓰지 않는다 — 검색 결과에는 아직 그쪽이 더 많다.
- 하이퍼파라미터 숫자를 적을 때는 **어느 환경 기준인지**를 같이 적는다. 맥락 없는 숫자는
  이 덱에서 안 쓴다.
