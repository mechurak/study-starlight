## 직무 지형

"강화학습 엔지니어"라는 단일 직무는 사실상 없다. 실제로는 이렇게 나뉜다.

| 직무 | 하는 일 | 핵심 요구 | 자리 수 |
|---|---|---|---|
| **LLM 후처리 (RLHF · RLVR)** | 선호·검증 보상으로 대형 모델 미세조정 | 분산 학습, 대규모 인프라, PyTorch 깊이 | <Badge text="가장 많다" variant="success" /> |
| **로봇 학습 엔지니어** | 시뮬 환경·보상·대규모 학습·sim-to-real | Isaac Lab/MuJoCo, 제어 기초, 실물 경험 | <Badge text="증가 중" variant="success" /> |
| **로봇 소프트웨어·배포** | 온보드 추론, ROS 2, 안전 층, 실시간성 | C++, 실시간 시스템, 하드웨어 감각 | <Badge text="꾸준" variant="note" /> |
| **시뮬레이션 엔지니어** | 물리·시장 시뮬레이터 자체를 만든다 | 수치해석 또는 미시구조, 성능 최적화 | <Badge text="희소하고 귀하다" variant="success" /> |
| **퀀트 (실행·마켓메이킹)** | 체결·호가 전략, RL은 그중 한 도구 | 시계열 검증, 미시구조, 저지연 | <Badge text="좁고 경쟁적" variant="caution" /> |
| **RL 응용 (추천·광고·제어)** | 밴딧·오프라인 RL로 제품 지표 개선 | 인과추론, A/B, 오프라인 평가 | <Badge text="꾸준" variant="note" /> |
| **연구자** | 새 알고리즘·이론 | 논문 실적, 수학 깊이 | <Badge text="매우 좁다" variant="caution" /> |

:::tip[핵심 — 두 개의 오해]
**오해 1 — "강화학습 = 연구직"**. 실제 채용의 대부분은 응용·인프라·시뮬레이션 쪽이고,
거기서 요구하는 것은 논문이 아니라 **돌아가게 만드는 능력**이다.

**오해 2 — "알고리즘을 잘 알면 된다"**. PPO를 구현할 줄 아는 사람은 흔하다.
변별력은 **환경을 잘 만드는 능력, 검증을 제대로 하는 능력, 도메인 지식**에서 나온다.
:::

## 6개월 학습 경로

주당 10~15시간을 가정한 현실적인 순서다. **각 단계의 산출물이 곧 포트폴리오**가 된다.

<Steps>

1. **기초 (4주)** — MDP · 벨만 · Q러닝을 **직접 구현**한다.

   표 기반 Q러닝으로 격자 세계를 풀고, 그다음 DQN을 카트폴에 붙인다.
   **CleanRL의 단일 파일 구현을 읽으며 따라 짜는 것**이 빠르다.
   산출물 — 시드 5개 결과 분포가 담긴 짧은 보고서.

2. **현대 알고리즘 (4주)** — PPO와 SAC를 돌리고 **차이를 실험으로 확인**한다.

   같은 연속 제어 과제에서 샘플 효율과 안정성을 비교한다.
   구현 디테일(정규화)을 껐다 켜 보며 영향을 잰다 ([6장](/rl/06-ppo-sac/)).

3. **환경을 직접 만든다 (3주)** — Gymnasium 환경을 하나 처음부터 쓴다.

   여기서 보상 설계와 종료 조건의 어려움을 실제로 겪는 것이 목적이다.
   **리워드 해킹을 한 번 당해 보는 것**이 이 단계의 진짜 소득이다.

4. **도메인을 고른다 (2주)** — 로봇이냐 트레이딩이냐.

   양쪽 다 얕게 하는 것보다 한쪽을 깊게 하는 편이 낫다.

5. **도메인 심화 (8주)**

   **로봇** — MuJoCo 과제 → Isaac Lab 보행 예제 → 도메인 무작위화 실험 →
   (가능하면) 저가 로봇 팔 + LeRobot로 시연 수집·모방학습.

   **트레이딩** — 누출 없는 백테스트 프레임워크 → 체결 시뮬레이터 →
   TWAP 기준선 대비 RL 체결 에이전트 → 워크포워드 검증.

6. **정리 (3주)** — 실험 하나를 **논문처럼 정리**한다.

   문제 정의, MDP 표, 기준선, 시드 분포, 절제 실험, 실패한 것과 그 이유.
   **실패를 정직하게 적은 보고서가 좋은 결과 자랑보다 좋은 평가를 받는다.**

</Steps>

## 포트폴리오 — 좋은 것과 나쁜 것

| 나쁜 것 | 왜 | 좋은 것 |
|---|---|---|
| "DRL 주식 봇, 연 수익 300%" | 누출·비용 누락이 거의 확실. **의심부터 받는다** | 누출 감사와 비용 민감도를 포함한 워크포워드 보고서 |
| 튜토리얼 재현 그대로 | 변별력이 없다 | 재현 + **절제 실험 + 시드 분포** |
| 알고리즘 목록 나열 | 깊이가 안 보인다 | 하나를 **깊게 분해**한 글 |
| 시뮬 성적만 있는 로봇 정책 | sim-to-real을 모른다는 신호 | 무작위화 범위에 따른 견고함 곡선, 실물 시도 기록 |
| 결과만 있는 리포지터리 | 재현 불가 | **설정·시드·로그·재현 절차**가 있는 리포지터리 |

:::caution[함정 — 결과를 과장하면 즉시 들킨다]
이 분야 면접관은 **10장의 질문들을 그대로 던진다** — 시드 몇 개인가,
평가 환경은 분리했는가, 기준선은 무엇인가, 비용을 두 배로 하면 어떻게 되는가.
과장된 숫자는 세 번째 질문 안에 무너지고, **정직하게 한계를 적은 프로젝트가 훨씬 좋게 평가받는다.**
:::

## 면접에서 실제로 나오는 것

| 유형 | 예 |
|---|---|
| 문제를 MDP로 옮기기 | "이 문제를 강화학습으로 푼다면 상태·행동·보상을 어떻게 두겠는가" |
| **판정** | "이 문제에 강화학습을 쓸 이유가 있는가" — [1장](/rl/01-why/) |
| 알고리즘 선택 | "왜 PPO인가, SAC가 아니라" |
| 디버깅 | "학습이 안 오른다. 무엇부터 보겠는가" — [9장](/rl/09-training/) |
| 보상 | "이 보상 함수의 허점은" — [8장](/rl/08-reward/) |
| 평가 | "이 결과를 어떻게 믿을 수 있는가" — [10장](/rl/10-evaluation/) |
| 도메인 | 로봇 — sim-to-real 처방 / 트레이딩 — 누출 사례 |

**절반이 "판정"과 "디버깅"** 이다. 알고리즘 유도를 물어보는 자리는 연구직에 가깝다.

## 17장 요약

- "강화학습 엔지니어"라는 단일 직무는 없다. **도메인 × 층**으로 자리가 정해진다
- 채용이 가장 많은 곳은 **LLM 후처리**이고, 그다음이 로봇 학습·시뮬레이션·응용이다
- 공통 기반은 **필요한 만큼의 수학 · 깊은 PyTorch · 실험을 재현하는 엔지니어링 · 환경 설계**
- 변별력은 알고리즘이 아니라 **환경을 만드는 능력, 검증하는 능력, 도메인 지식**에서 나온다
- 로봇이면 **제어 기초 · ROS 2 · 시뮬레이터 · 실물 경험**, 트레이딩이면 **시계열 검증 · 미시구조 · 데이터**
- **도메인을 하나 고른다.** 겹치는 능력(환경 설계·평가 설계)은 어느 쪽으로 가든 남는다
- 6개월 경로 — **기초 구현 → 현대 알고리즘 비교 → 환경 직접 제작 → 도메인 선택 → 심화 → 정리**
- 포트폴리오는 **수익률 자랑이 아니라 재현 가능성과 정직한 한계**로 평가받는다
- 면접의 절반은 **"이 문제에 RL을 쓸 이유가 있는가"와 "안 될 때 무엇부터 보는가"** 다
