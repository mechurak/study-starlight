## 먼저 풀려는 문제

직원은 이미 Paseo에서 repository를 고르고 coding agent에게 prompt를 보낸다. 회사 표준 prompt나
승인된 MCP tool을 쓰기 위해 별도 포털을 열고 내용을 복사해야 한다면 문맥이 끊기고, 최신 버전인지도
확신하기 어렵다. 필요한 것은 거대한 사내 포털이 아니라 **현재 agent 작업에 붙는 작은 카탈로그**다.

```text
찾기 → 설명과 권한 확인 → 현재 작업에 붙이기 → 실행 결과를 Paseo에서 계속 보기
```

Paseo plugin은 이 흐름의 첫 세 단계를 같은 sidebar 안에 둘 수 있다. 일반 Paseo 작업은
`usePaseo()` SDK로 수행하고, 사내 API나 credential이 필요한 작업은 daemon-side RPC handler로
보낸다. 이 분리는 [Paseo가 공식적으로 제시하는 plugin 사용 모델](https://paseo.sh/docs/plugins/reference)과 맞는다.

## 잘 맞는 범위와 경계

<Card title="Paseo plugin이 잘 맞는다" icon="approve-check">
회사 prompt를 검색해 새 agent를 시작한다.

승인된 skill 버전과 설명을 보고 로컬에 설치한다.

MCP tool을 현재 agent 설정에 추가한다.

작은 운영 dashboard를 agent 작업 옆에서 확인한다.

사내 자료를 composer attachment로 붙인다.
</Card>
<Card title="별도 웹 앱이 낫다" icon="warning">
대형 table과 복잡한 입력 form이 화면의 중심이다.

결재선·알림·실시간 협업이 독립 제품 수준이다.

웹 전용 component library와 browser API가 필수다.

Paseo를 쓰지 않는 임직원도 같은 기능을 써야 한다.

관리자용 catalog authoring UI가 필요하다.
</Card>
</CardGrid>

Paseo client contribution이 import할 수 있는 runtime module은 React, React Native, TanStack Query,
Zod와 plugin API 등으로 제한된다. 따라서 기존 웹 dashboard를 그대로 embed할 수 있다고 가정하지
않는다. 작은 dashboard는 surface로 그리고, 복잡한 기존 화면은 SSO가 적용된 URL을 기본 browser로 연다.

## 책임을 다섯 곳에 나눈다

| 구성 요소 | 소유하는 것 | 소유하지 않는 것 |
|---|---|---|
| plugin surface | 탐색 UI, loading·error·재로그인 상태 | 최종 권한 판정, 장기 token |
| plugin handler | OIDC 흐름, token 갱신, Catalog API 호출 | 조직정보의 정본, 전사 배포 정책 |
| Keycloak | 사용자 인증, AD identity·group claim | catalog 항목별 정책 |
| oauth2-proxy | cookie/JWT 검증, 서비스 1차 진입 통제 | 개인·부서별 항목 조합 |
| Catalog API | entitlement 계산, 허용된 metadata·artifact | PC의 agent 실행 생명주기 |

:::tip[핵심 원칙]
Paseo plugin은 권한을 **표현**하지만 권한의 정본은 아니다. 개발자 도구에서 버튼을 숨기는 것과
API 요청을 거부하는 것은 다른 통제다.
:::

## 도입 전에 답할 질문

- 회사가 배포할 plugin의 owner와 release channel은 누구인가
- 사용자 identity는 Keycloak의 어떤 realm과 client에서 발급되는가
- 개인·부서·직무 권한은 Keycloak role인가, 별도 entitlement DB인가
- skill과 prompt를 내려받은 뒤 권한이 회수되면 무엇을 할 수 있어야 하는가
- tool 실행은 어느 서버가 매번 재인가하는가
- Windows·macOS·Linux 중 지원할 PC와 credential store는 무엇인가

이 질문에 답하지 않은 채 UI부터 만들면 catalog는 보여도 통제 가능한 사내 제품은 되지 않는다.
