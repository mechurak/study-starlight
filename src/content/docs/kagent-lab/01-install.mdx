## 사전 준비

Docker·kind·kubectl은 운영체제에 맞는 [macOS 준비](/lab-environment/01-kind-macos/) 또는
[Ubuntu 준비](/lab-environment/02-kind-ubuntu/)를 먼저 따른다. 이어서 공통 도구인
[Helm CLI](/lab-environment/04-helm/)를 준비한다. 이 장은 kagent 전용인 CLI 설치부터 맡는다.

```bash
docker info
kind version
kubectl version --client
helm version
```

확인 당시 kagent 공식 설치 문서의 기본 CLI release는 `0.9.9`다. 출력이 다르면 실패는 아니지만 이 덱의
CR 예시와 맞는지 [release notes](https://kagent.dev/docs/kagent/resources/release-notes)를 먼저 본다.

## kagent CLI 설치

<Tabs>
<TabItem label="macOS — Homebrew">

kagent 공식 설치 문서의 Homebrew 경로를 사용한다.

```bash
brew install kagent
kagent version
```

이미 설치되어 있다면 다음 명령으로 갱신하고 version을 다시 확인한다.

```bash
brew upgrade kagent
kagent version
```

</TabItem>
<TabItem label="Ubuntu — 공식 installer">

공식 `get-kagent` installer는 release binary와 SHA256을 함께 받아 검증한다. installer 자체도 먼저 파일로
내려받아 download URL, checksum 검증, 설치 위치를 확인한 뒤 실행한다.

```bash
sudo apt-get update
sudo apt-get install -y curl git jq openssl tar
curl -fsSL -o /tmp/get-kagent \
  https://raw.githubusercontent.com/kagent-dev/kagent/refs/heads/main/scripts/get-kagent
```

`/tmp/get-kagent`를 editor로 열어 내용을 검토한다. 기본 설치 위치는 `/usr/local/bin/kagent`이고 실행 중
필요하면 `sudo`를 요청한다.

```bash
chmod 700 /tmp/get-kagent
/tmp/get-kagent
kagent version
```

설치가 끝나고 더 확인할 필요가 없을 때 installer만 지운다.

```bash
rm /tmp/get-kagent
```

관리자 권한 없이 `$HOME/bin`에 설치하려면 installer의 `--no-sudo` 옵션과 출력되는 `PATH` 안내를 따른다.

</TabItem>
</Tabs>

:::caution[checksum 오류를 우회하지 않는다]
installer가 release binary의 checksum 불일치로 중단되면 검증을 끄지 않는다. 내려받은 파일을 지우고 공식
release와 네트워크 경로를 확인한 뒤 다시 시도한다.
:::

## 전용 cluster에 kagent 설치

<Steps>

1. **전용 kind cluster를 만든다**

   ```bash
   kind create cluster --name kagent-lab --wait 5m
   ```

2. **현재 context를 문자열로 확인한다**

   ```bash
   kubectl config current-context
   ```

   기대값은 정확히 `kind-kagent-lab`이다. 다르면 다음 명령으로 바꾼 뒤 다시 확인한다.

   ```bash
   kubectl config use-context kind-kagent-lab
   ```

3. **선택한 API key가 현재 shell에 있는지만 확인한다**

   OpenAI 직접 연결은 `OPENAI_API_KEY`를 그대로 쓴다. LiteLLM 경로에서는 kagent installer의 provider 입력
   계약을 통과하도록 virtual key를 설치 순간에만 같은 이름으로 연결한다. 이것만으로 endpoint가 바뀌지는 않으며,
   설치 뒤 `ModelConfig`의 `baseUrl`을 반드시 바꾼다.

   ```bash
   if test -n "$LITELLM_API_KEY" && test -z "$OPENAI_API_KEY"; then
     export OPENAI_API_KEY="$LITELLM_API_KEY"
   fi
   test -n "$OPENAI_API_KEY" && echo "OPENAI_API_KEY is set"
   ```

4. **학습용 demo profile을 설치한다**

   ```bash
   kagent install --profile demo
   ```

   이 명령은 현재 Kubernetes context를 대상으로 한다. 실행 직전에 context를 확인한 이유다.

</Steps>

`kagent install`은 설치를 별도로 구현하지 않고 host의 `helm` executable로 다음 두 release를
`upgrade --install`한다. `demo` profile은 CLI에 내장된 values를 두 번째 release에 전달한다.

```text
kagent-crds  → Agent·ModelConfig·MCP 관련 CRD
kagent       → controller·UI·DB·default ModelConfig·sample Agent와 tool
```

실제 Helm 소유권과 이력을 확인한다.

```bash
helm -n kagent list
helm -n kagent status kagent
helm -n kagent status kagent-crds
helm -n kagent history kagent
```

## control plane 확인

설치 성공 문장만 믿지 않고 실제 resource를 본다.

```bash
kubectl get crd | grep kagent.dev
kubectl -n kagent get pods
kubectl -n kagent get svc
kubectl -n kagent get modelconfig
```

CRD 목록에는 `agents.kagent.dev`, `modelconfigs.kagent.dev` 같은 type이 있고, `kagent` namespace의 control
plane Pod는 시간이 지나면 `Running`·ready가 된다. `default-model-config`가 있어야 뒤 장의 Agent가 참조할 수 있다.

:::tip[Pod Running과 Agent Ready는 다른 상태]
controller와 UI가 떠도 model credential이 잘못됐거나 tool server가 준비되지 않으면 Agent 호출은 실패할 수 있다.
설치는 control plane 확인이고, 다음 장의 실제 질문이 data plane 확인이다.
:::

## dashboard 열기

```bash
kagent dashboard
```

CLI가 port-forward를 열고 로컬 주소를 출력한다. 이 terminal을 유지한 채 dashboard에서 sample Agent와 tool
목록을 둘러본다. 종료는 `Ctrl+C`다. 포트 번호를 외우지 말고 CLI가 이번 실행에 출력한 주소를 사용한다.

## OpenAI 대신 사내 LiteLLM 연결하기

OpenAI API를 직접 쓸 수 없다면 2장의 첫 호출 전에 이 절을 수행한다. kagent에는 LiteLLM 전용 provider를
지정하는 대신 OpenAI-compatible provider와 `openAI.baseUrl`을 조합한다.

```text
sample/custom Agent → default-model-config → 사내 LiteLLM /v1 → 허용된 upstream model
```

먼저 별도 Secret을 만든다. 같은 명령을 다시 실행해도 해당 key만 갱신되는 형태다.

```bash
test -n "$LITELLM_API_KEY" && \
  test -n "$LITELLM_BASE_URL" && \
  test -n "$LITELLM_MODEL" && \
  echo "LiteLLM inputs are set"
kubectl -n kagent create secret generic kagent-litellm \
  --from-literal=LITELLM_API_KEY="$LITELLM_API_KEY" \
  --dry-run=client -o yaml | kubectl apply -f -
```

이 kind 실습에서는 demo Agent들이 공유하는 `default-model-config`를 한 번 바꿔 모두 같은 gateway를 보게 한다.
shell 변수에는 key가 아니라 URL과 공개 model alias만 들어간다.

```bash
kubectl -n kagent patch modelconfig default-model-config --type merge \
  -p "{\"spec\":{\"apiKeySecret\":\"kagent-litellm\",\"apiKeySecretKey\":\"LITELLM_API_KEY\",\"provider\":\"OpenAI\",\"model\":\"${LITELLM_MODEL}\",\"openAI\":{\"baseUrl\":\"${LITELLM_BASE_URL}\"}}}"
```

설정값과 영향받는 Agent를 확인한다. Secret 값은 출력하지 않는다.

```bash
kubectl -n kagent get modelconfig default-model-config \
  -o jsonpath='{.spec.provider}{"\t"}{.spec.model}{"\t"}{.spec.openAI.baseUrl}{"\n"}'
kubectl -n kagent get agents \
  -o custom-columns='AGENT:.metadata.name,TYPE:.spec.type,MODEL_CONFIG:.spec.declarative.modelConfig'
```

`default-model-config`를 참조한 Agent는 모두 같은 변경의 영향을 받는다. Pod와 Agent condition이 다시 안정되는지
확인하고 2장에서 실제 tool 호출까지 수행해야 전환이 끝난다. LiteLLM의 model alias 뒤 upstream도 function/tool
calling과 `tool_choice: auto`를 지원해야 한다. kagent는 사용자 tool을 하나도 넣지 않아도 built-in tool을 포함한
요청을 보낼 수 있다.

### UI에서 LiteLLM model 목록 가져오기

dashboard의 **Models → New Model**은 `ModelConfig` 생성 화면이다. **Custom parameters**는 첫 화면에 바로
보이는 것이 아니라 provider와 model을 모두 선택한 뒤 나타난다. OpenAI provider에서는 그 안의 `baseUrl`에
LiteLLM `/v1` 주소를 넣는다.

model 입력은 자유 text가 아니라 목록 선택이다. LiteLLM의 `/v1/models`를 목록으로 쓰려면 provider discovery를
한 번 bootstrap한다. `ModelProviderConfig`의 Secret은 정확히 data key 하나만 가져야 하므로 앞의
`kagent-litellm` Secret을 그대로 참조할 수 있다.

```bash
kubectl apply -f - <<EOF
apiVersion: kagent.dev/v1alpha2
kind: ModelProviderConfig
metadata:
  name: company-litellm
  namespace: kagent
spec:
  type: OpenAI
  endpoint: ${LITELLM_BASE_URL}
  secretRef:
    name: kagent-litellm
EOF
```

```bash
kubectl -n kagent get modelproviderconfig company-litellm -o yaml
```

이후 UI에서 **Configured Providers → company-litellm → Fetch Models → model 선택** 순서로 간다. model을
선택하면 **Custom parameters**가 나타난다. v0.9.9 UI에서는 discovery에 쓴 endpoint와 credential을 새
`ModelConfig`에 자동 복사하지 않으므로 API key를 다시 입력하고 `baseUrl`도 명시한다.

### private CA와 Helm drift 처리

사내 TLS가 public trust store에 없다면 검증을 끄지 말고 CA bundle Secret을 `ModelConfig.spec.tls`로 참조한다.

```bash
kubectl -n kagent create secret generic llm-certs \
  --from-file=ca.crt=company-ca.crt
kubectl -n kagent patch modelconfig default-model-config --type merge \
  -p '{"spec":{"tls":{"caCertSecretRef":"llm-certs","caCertSecretKey":"ca.crt"}}}'
```

이 TLS 설정은 Agent runtime의 model 호출에 적용된다. `ModelProviderConfig`의 model discovery에도 같은 사내 CA가
필요하지만 해당 resource에는 별도 TLS 필드가 없다. controller가 그 CA를 신뢰하도록 배포 설정을 관리할 수 없다면
UI의 **Fetch Models**는 건너뛰고 위처럼 `ModelConfig`를 YAML·patch로 직접 설정한다.

:::caution[빠른 일괄 전환과 선언적 운영을 구분한다]
`default-model-config`는 Helm chart가 만든 resource다. 위 patch는 실습에는 간단하지만 다음
`kagent install --profile demo`나 Helm upgrade가 원래 values로 되돌릴 수 있다. 운영에서는
`litellm-default` 같은 별도
`ModelConfig`와 `ModelProviderConfig`를 GitOps manifest로 관리하고, 검증한 Agent부터 그 이름으로 옮긴다.
:::

## 안 될 때 먼저 볼 것

| 증상 | 확인 |
|---|---|
| 설치가 엉뚱한 cluster를 가리킴 | 즉시 중단하고 `kubectl config current-context` 확인 |
| Pod가 `Pending` | `kubectl -n kagent describe pod <이름>`의 Events와 메모리 |
| `ImagePullBackOff` | Pod Events, registry 접근, proxy·DNS |
| model config가 없음 | `kagent install` 출력과 controller log |
| LiteLLM model 목록이 비어 있음 | `ModelProviderConfig` condition, `/v1/models`, key scope와 DNS·TLS |
| LiteLLM 호출이 `400` | 공개 model alias와 upstream의 tool calling 지원 |
| dashboard가 안 열림 | `kubectl ... get svc`, UI Pod log, 로컬 포트 충돌 |

설치 문제가 남으면 공식 debug 절의 첫 상태를 모은다.

```bash
kubectl -n kagent logs deployment/kagent-controller --tail=100
```

## 완료 체크

- `kubectl config current-context`가 `kind-kagent-lab`이다.
- kagent CRD, control plane Pod, `default-model-config`를 확인했다.
- LiteLLM을 선택했다면 `default-model-config`의 model·`baseUrl`과 참조 Agent를 확인했다.
- `kagent`와 `kagent-crds`가 Helm release라는 것을 확인했다.
- dashboard에서 sample Agent를 볼 수 있다.
- cluster는 지우지 않는다. 다음 장에서 그대로 쓴다.
