## Pod 기초 — Practice Test: PODs

원본 풀이: [13-Practice-Test-PODs.md](https://github.com/kodekloudhub/certified-kubernetes-administrator-course/blob/master/docs/02-Core-Concepts/13-Practice-Test-PODs.md)

| 과제 | 명령 |
|---|---|
| Pod 개수 세기 — *How many pods exist on the system?* | `k get pods --no-headers \| wc -l` |
| Pod 만들기 — *Create a new pod with the nginx image.* | `k run nginx --image=nginx` |
| 이미지·노드 확인 — *What is the image used to create the new pods? / Which nodes are these pods placed on?* | `k get pods -o wide` 또는 `k describe pod <name>` |
| 컨테이너 상태·에러 원인 — *What is the state of the container agentx in the pod webapp? / Why do you think the container agentx in pod webapp is in error?* | `k describe pod <name>` → State / Events |
| Pod 삭제 (빠르게) — *Delete the webapp Pod.* | `k delete pod webapp --force` |
| YAML 뽑아서 생성 — *Create a new pod with the name redis and with the image redis123. Use a pod-definition YAML file.* | `k run redis --image=redis123 --dry-run=client -o yaml > redis.yaml` |

(`--dry-run=client`는 서버에 요청을 보내지 않고 클라이언트에서 검증만 하고 끝낸다는 뜻이다 —
`-o yaml`과 짝지으면 "만들지 말고 YAML만 뽑기"가 된다. 이 덱 전체에서 반복되는 콤보다.)

*Now change the image on this pod to redis. Once done, the pod should be in a running state.* —
이미지 이름이 틀린 Pod(`redis123`)을 고치는 방법은 셋 다 알아둔다 —

```bash
# 1) 매니페스트 고치고 apply
vi redis.yaml && kubectl apply -f redis.yaml
# 2) 실행 중인 Pod을 직접 편집 (image는 편집 가능한 몇 안 되는 필드)
kubectl edit pod redis
# 3) image만 바로 교체 — pod/<pod이름> <컨테이너이름>=<새이미지>
kubectl set image pod/redis redis=redis
```

:::tip[READY 열 읽는 법]
*What does the READY column in the output of the kubectl get pods command indicate?* —
`READY 1/2`는 "컨테이너 2개 중 1개 준비됨"이다. Pod 개수가 아니라
**컨테이너 준비 수 / 전체 수** — 멀티 컨테이너 문제에서 반복해서 나온다.
:::

:::caution[함정 — --force]
`--force`는 시험에서는 시간을 벌어주지만, 실무에서는 정리 작업(preStop 등)을
건너뛴 채 컨테이너를 남길 수 있는 최후 수단이다. 시험용 습관과 실무 습관을 구분할 것.
:::

## 네임스페이스 — Practice Test: Namespaces

원본 풀이: [19-Practice-Test-Namespaces.md](https://github.com/kodekloudhub/certified-kubernetes-administrator-course/blob/master/docs/02-Core-Concepts/19-Practice-Test-Namespaces.md)

| 과제 | 명령 |
|---|---|
| 네임스페이스 목록 — *How many Namespaces exist on the system?* | `k get ns` |
| 특정 ns의 Pod — *How many pods exist in the research namespace?* | `k get pods -n research` |
| 전체 ns에서 찾기 — *Which namespace has the blue pod in it?* | `k get pods -A \| grep blue` |
| ns 지정해 생성 — *Create a POD in the finance namespace.* | `k run redis --image=redis -n finance` |

DNS 이름 규칙이 이 랩의 진짜 출제 포인트다 —

- **같은 네임스페이스**의 Service: 호스트 이름만 — `db-service`
  — *What DNS name should the Blue application use to access the database db-service in its own namespace - marketing?*
- **다른 네임스페이스**(dev)의 Service: `db-service.dev` 또는
  풀 네임 `db-service.dev.svc.cluster.local`
  — *What DNS name should the Blue application use to access the database db-service in the dev namespace?*

원리는 [cka 10장 이름 규칙](/cka/10-dns/)에 있다.

## 명령형 커맨드 — Practice Test: Imperative Commands

원본 풀이: [24-Practice-Test-Imperative-Commands.md](https://github.com/kodekloudhub/certified-kubernetes-administrator-course/blob/master/docs/02-Core-Concepts/24-Practice-Test-Imperative-Commands.md)

YAML을 열지 않고 한 줄로 끝내는 연습이다. 전부 손에 붙여둘 것 —

```bash
# "Deploy a pod named nginx-pod using the nginx:alpine image."
kubectl run nginx-pod --image=nginx:alpine
# "Deploy a redis pod using the redis:alpine image with the labels set to tier=db."
kubectl run redis --image=redis:alpine -l tier=db          # 라벨 지정
# "Create a new pod called custom-nginx using the nginx image and expose it on container port 8080."
kubectl run custom-nginx --image=nginx --port=8080          # containerPort 지정
# "Create a service redis-service to expose the redis application within the cluster on port 6379."
kubectl expose pod redis --port=6379 --name redis-service   # ClusterIP Service. 여기의 --port는 Service 포트 — run의 --port(containerPort)와 다른 뜻
# "Create a new namespace called dev-ns."
kubectl create ns dev-ns
# "Create a deployment named webapp using the image kodekloud/webapp-color with 3 replicas."
kubectl create deployment webapp --image=kodekloud/webapp-color --replicas=3
# "Create a new deployment called redis-deploy in the dev-ns namespace with the redis image. It should have 2 replicas."
kubectl create deployment redis-deploy -n dev-ns --image=redis --replicas=2
```

:::tip[Pod + Service 한 줄]
"Pod을 만들고 같은 이름의 ClusterIP Service로 노출하라"는 문제는
`--expose`가 한 줄로 끝낸다 —

```bash
# "Create a pod called httpd using the image httpd:alpine in the default namespace. Next, create a service of type ClusterIP by the same name (httpd). The target port for the service should be 80."
kubectl run httpd --image=httpd:alpine --expose --port 80
```
:::

## JSONPath와 정렬 — Practice Test: Advanced Kubectl Commands

원본 풀이: [04-Practice-Test-Advance-Kubectl-Commands.md](https://github.com/kodekloudhub/certified-kubernetes-administrator-course/blob/master/docs/13-Other-Topics/04-Practice-Test-Advance-Kubectl-Commands.md)

출력 가공 네 가지 패턴이 전부다. 문법은 [cka 3장 조회와 출력](/cka/03-kubectl/)에 정리돼 있다.

```bash
# 1) JSON 통째로 저장
kubectl get nodes -o json > /opt/outputs/nodes.json
# 2) JSONPath로 필드만 뽑기 — get <복수 리소스>의 출력은 List라 .items[*]로 전 항목을 편다
kubectl get nodes -o jsonpath='{.items[*].metadata.name}'
kubectl get nodes -o jsonpath='{.items[*].status.nodeInfo.osImage}'
# 3) 정렬과 커스텀 열
kubectl get pv --sort-by=.spec.capacity.storage \
  -o custom-columns=NAME:.metadata.name,CAPACITY:.spec.capacity.storage
# 4) 필터 표현식 — ?()가 필터, @는 검사 중인 항목 자신 (특정 user를 쓰는 context 찾기)
kubectl config view --kubeconfig=my-kube-config \
  -o jsonpath="{.contexts[?(@.context.user=='aws-user')].name}"
```

:::caution[함정 — 결과를 파일로]
이 유형은 대부분 "**결과를 지정된 파일에 저장하라**"까지가 문제다.
명령이 맞아도 리다이렉트(`> /opt/outputs/...`)를 빼먹으면 0점이다.
:::

## 이 장에서 남길 것

- 모든 진단은 `get → describe → Events`로 시작한다
- `--dry-run=client -o yaml`이 YAML 작성의 출발점이다
- 만들라는 명령(`run`/`create`/`expose`)은 한 줄로, 고치라는 명령은 `edit`/`set image`/`apply` 셋 중에서
- DNS는 `<service>.<namespace>`만 기억하면 대부분 풀린다
