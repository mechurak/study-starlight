> 문제를 받았을 때 손이 먼저 나가게 — 실습 풀이 패턴 모음

유데미 CKA 강의의 참고 레포 [`certified-kubernetes-administrator-course`](https://github.com/kodekloudhub/certified-kubernetes-administrator-course)에 요약된
**KodeKloud 실습(Practice Test) 풀이 44개**를, [cka 덱](/cka/)의 장 순서로 재편성했다.
레포에 풀이가 없는 **2025년 신규 랩 4개**(admission 컨트롤러 2개, Calico CNI 설치, Helm)는
[KodeKloud 노트 사이트](https://notes.kodekloud.com/docs/Certified-Kubernetes-Administrator-CKA/)와 랩 원문을 소스로 보강했다.
개념 설명은 cka 덱이 맡고, 이 덱은 "**이런 문제가 나오면 이렇게 푼다**"만 맡는다.

여기에 다른 실습을 수행하며 얻은 **완료 판정·실패 분기·복구 후 재검증 패턴**도 덧붙인다.
긴 원본은 수정 대상과 성공 조건에 따라 39개 작업 페이지로 나눴다. 페이지 첫 두 문단에서
할 일을 파악하고, 본문의 명령과 공식 문서 검색 경로를 따라간 뒤 완료 기준으로 기능을 판정한다.
특정 랩 환경·설치된 CRD·선택 기능 사례는 필수 범위처럼 보이지 않도록 학습 보충으로 표시했다.

## 이 덱을 읽는 법

처음 학습할 때는 구성도에 놓인 순서로 읽는다. 문제를 풀다가 찾을 때는
[작업 색인](/cka-udemy/exam-search/)에서 문제의 동사와 리소스에 맞는 첫 명령을 고른다.
각 실습 페이지에서는 다음 네 단계만 확인하면 된다.

1. **목표 파악** — 첫 두 문단에서 수정할 대상과 성공 조건을 찾는다.
2. **명령 선택** — 현재 상태를 먼저 조회하고 요구된 최소 필드만 바꾼다.
3. **공식 예제 찾기** — 페이지의 영문 검색어로 시험 버전에 맞는 문서 절을 연다.
4. **성공 판정** — 오브젝트 존재와 실제 기능을 구분하고, 복구라면 원래 실패한 요청을 반복한다.

## cka 덱과의 관계

- **cka 덱은 "왜 그런가", 이 덱은 "시키면 어떻게 하나"다**. 같은 주제를 두 번 설명하지 않는다 —
  각 장 첫머리에 짝이 되는 cka 장을 걸어 뒀고, 원리가 궁금하면 그리로 간다.
- 실습마다 원본 레포(GitHub)의 풀이 문서 링크를 남겼다. 같은 내용을 웹으로 훑기에는
  [KodeKloud 노트 사이트](https://notes.kodekloud.com/docs/Certified-Kubernetes-Administrator-CKA/)가 편하다.
  **읽는 것으로 끝내지 말고 KodeKloud 랩에서 직접 칠 것** —
  이 덱은 랩을 돌기 전의 예습과 돈 뒤의 복습용이다.
- 원본 레포는 유데미 강의 시점의 구버전 Kubernetes 기준이다. **명령이 낡은 곳은
  시험 환경(v1.35) 기준으로 고쳐 실었고**, 고친 자리마다 표시를 남겼다.
- `Practice Test` 제목이 없는 절은 특정 문제의 추가 해답이 아니라, 실습 뒤에도 성공 여부를 판정하고
  실패 지점을 좁힐 수 있도록 보강한 출처 중립적 검증 루프다. 현재 동작의 근거는 절마다 공식 문서로 남긴다.
- 각 장 끝의 **시험장에서 공식 문서 찾기** 표는 `영문 검색어 → 공식 페이지 → YAML에서 복사할 블록`을
  연결한다. 시험 브라우저에서는 검색어를 그대로 입력하고, 개념 설명보다 예제 매니페스트 제목으로 바로 이동한다.
  링크는 항상 최신인 기본 주소를 쓰므로, API·설치·업그레이드 절차가 시험 버전과 다르면 페이지 상단
  **Versions**에서 시험 클러스터 버전으로 바꾼다.

## 원본 풀이에서 직접 가져오지 않은 것

원본 레포의 Practice-Test 문서는 51개다. 아래 7개 문서는 비어 있거나 현 범위와 맞지 않아
풀이 원문을 직접 쓰지 않았다. 같은 주제의 보강 실습이 있는 경우 목적 페이지를 함께 적었다.

| 실습 | 제외 이유 |
|---|---|
| Core Concepts Introduction | 원본이 빈 껍데기 — 풀이 요약이 없다 |
| Control Plane Failure | 원본은 빈 껍데기. 실제 오류 사례와 공식 진단 순서는 [컨트롤 플레인 복구](/cka-udemy/control-plane-failure/)에 보강했다 |
| Worker Node Failure | 원본은 빈 껍데기. kubelet 오류 사례와 공식 진단 순서는 [워커 노드 복구](/cka-udemy/worker-failure/)에 보강했다 |
| CNI weave | Weave는 단종됐고 현 시험 환경에 없다. 다만 런타임 엔드포인트·CNI 디렉터리를 확인하는 두 문항은 [네트워크 환경과 CNI 확인](/cka-udemy/network-environment/)에 살려 뒀다 |
| Networking weave | 위와 같다 |
| Deploy Network Solution | 풀이가 "weave를 설치하라" 한 줄이다. 현행 과정의 대체 랩(Install Calico CNI)은 [네트워크 환경과 CNI 확인](/cka-udemy/network-environment/#calico-설치--lab-install-calico-cni-2025-신규)에 있다 |
| Multiple Schedulers | 현 커리큘럼(v1.35)에 없는 항목이다 |

## 실습이 아직 없는 커리큘럼 범위

개념 덱에서 설명하지만 이 덱에 독립적인 end-to-end 실습이 없는 범위도 숨기지 않는다.

| 범위 | 현재 연결 |
|---|---|
| HA control plane 전체 구축 | [CKA kubeadm — 클러스터 설치와 노드 조인](/cka/cluster-setup/). [etcd 백업과 복구](/cka-udemy/etcd-backup-restore/)의 stacked/external etcd 구분은 일부 사례일 뿐이다 |
| CSI 드라이버 설치 | [CKA 스토리지](/cka/storage/)과 [CKA 확장 인터페이스 — CRI·CNI·CSI](/cka/extensions/). PV/PVC·StorageClass 실습만 있다 |
| 독립 operator 종합 설치 | [CKA 확장 인터페이스 — CRI·CNI·CSI](/cka/extensions/). Calico·VPA는 부분 사례다 |
| probes 전용 실습 | [CKA Pod — 배포의 최소 단위](/cka/pods/). 현재 Pod·Deployment 페이지에는 상태 확인과 controller 복구만 있다 |
| LoadBalancer 외부 IP | [CKA Service](/cka/services/). 이 덱의 실제 외부 요청은 NodePort·Ingress 중심이다 |
| Helm/Kustomize로 클러스터 컴포넌트 설치 | [Helm](/cka-udemy/helm/)·[Kustomize](/cka-udemy/kustomize/)는 release·manifest 적용 연습이며 별도 컴포넌트 설치 랩은 없다 |

:::tip[시험 직전에는]
이 덱을 처음부터 다시 읽지 말고, 각 장의 **함정 aside만** 훑은 뒤
[작업 색인](/cka-udemy/exam-search/)과 [CKA 시험 전략과 치트시트](/cka/exam-strategy/)로 넘어간다.
:::
