<Thesis>
레지스트리 자격증명을 Secret으로 만들고 Pod 템플릿의 imagePullSecrets에 연결해 프라이빗 이미지 다운로드를 해결한다.
</Thesis>

프라이빗 이미지를 받으려면 kubelet이 레지스트리에 제시할 자격증명이 필요하다.
이 실습은 Deployment `web`의 이미지와 Secret 참조를 수정한다.
[ServiceAccount 토큰 실습](/cka-udemy/service-account/)에서 다룬 Kubernetes API 인증과는 별도 작업이다.

> 짝이 되는 개념 장: [CKA 설정과 리소스](/cka/config/)

아래 명령은 `kubectl`이 설정된 실습 터미널에서 실행하며 현재 namespace는 `default`로 가정한다.
다른 namespace가 주어지면 모든 명령에 `-n <namespace>`를 붙인다.
`<pod-name>`은 `web` Deployment에 속한 실제 Pod 이름으로 바꾼다.
공식 참고 문서는 [Pull an Image from a Private Registry](https://kubernetes.io/docs/tasks/configure-pod-container/pull-image-private-registry/)다.

## 현재 이미지와 실패 원인 확인하기

```bash
kubectl get deploy web -o yaml
kubectl get pods
kubectl describe pod <pod-name>
```

Deployment의 `spec.template.spec`에서 image와 `imagePullSecrets`를 확인한다.
Pod Events에서 인증 실패인지, 이미지 주소나 연결 문제인지 구분한 뒤 문제에서 요구한 값으로 수정한다.

## Secret 생성 옵션 찾기

학습용 원본 풀이: [Practice Test: Image Security](https://github.com/kodekloudhub/certified-kubernetes-administrator-course/blob/master/docs/07-Security/24-Practice-Test-Image-Security.md)

먼저 도움말에서 Secret 종류를 찾고, `docker-registry`의 옵션과 Examples를 확인한다.
서버·사용자·비밀번호·이메일은 문제에서 제공한 값으로 채운다.

```bash
kubectl create secret -h
kubectl create secret docker-registry -h
```

아래는 원본 랩의 값으로 채운 예다. 다른 문제에서는 Secret 이름과 자격증명을 그대로 복사하지 않는다.

**문서 찾기:** Kubernetes 공식 사이트 내부에서 `Pull an Image from a Private Registry`를 검색한다.
[Create a Secret by providing credentials on the command line](https://kubernetes.io/docs/tasks/configure-pod-container/pull-image-private-registry/#create-a-secret-by-providing-credentials-on-the-command-line)
절의 명령에서 Secret 이름·서버·사용자·비밀번호를 문제 값으로 바꾼다.

```bash
kubectl create secret docker-registry private-reg-cred \
  --docker-server=myprivateregistry.com:5000 \
  --docker-username=dock_user \
  --docker-password=dock_password \
  --docker-email=dock_user@myprivateregistry.com
```

## Deployment에 Secret 연결하기

`kubectl edit deploy web`으로 Deployment를 연다. 같은 공식 페이지의
[Create a Pod that uses your Secret](https://kubernetes.io/docs/tasks/configure-pod-container/pull-image-private-registry/#create-a-pod-that-uses-your-secret)
절에서 `imagePullSecrets` 블록을 가져와 `spec.template.spec` 아래에 넣는다.
아래는 발췌이며, Secret은 workload와 같은 namespace에 있어야 한다.

```yaml
      imagePullSecrets:
      - name: private-reg-cred
```

같은 편집에서 대상 컨테이너의 이미지를 `myprivateregistry.com:5000/nginx:alpine`으로 바꾼다.
`docker-registry`는 생성 명령의 종류이고, 만들어진 Secret의 실제 타입은
`kubernetes.io/dockerconfigjson`이다.

## 이미지 다운로드 완료 확인하기

```bash
kubectl rollout status deploy web
kubectl get secret private-reg-cred
kubectl get pods
kubectl describe pod <pod-name>
```

새 Pod가 이미지를 받아 준비 상태가 되는지 확인한다. `ImagePullBackOff`는 이미지 다운로드의
재시도를 늦추고 있다는 뜻이다. Secret 미존재만을 뜻하지 않으므로 Pod Events에서
레지스트리 인증 실패·이미지 이름 오류·연결 실패를 구분한다.
