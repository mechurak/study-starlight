## 문제부터 — 이름이 없으면 무슨 일이 생기나

프로젝트 6개월 차, 디자이너가 말한다. **"브랜드 색을 남색에서 초록으로 바꿉시다."**

<Tabs>
<TabItem label="이름이 없을 때">

```tsx
<button className="bg-blue-600 text-white">저장</button>
<div className="border-blue-600">…</div>
<a className="text-blue-600">더 보기</a>
<span className="bg-blue-50 text-blue-900">진행 중</span>
```

- `blue-600`이 몇 군데 있는지 **아무도 모른다**. 전체 검색하면 214군데가 나온다
- 그중 어떤 게 "브랜드 색"이고 어떤 게 "그냥 파란색 안내 문구"인지 **구분이 안 된다**
- `blue-50`, `blue-900`처럼 **같은 결정에서 파생된 것들**도 따로 찾아야 한다
- 다 바꾸고 나면 **다크 모드가 깨진다.** 다크용 `dark:bg-blue-400`도 따로 있었기 때문

작업 견적: **2~3일 + 회귀 테스트.**

</TabItem>
<TabItem label="이름이 있을 때">

```tsx
<button className="bg-primary text-primary-foreground">저장</button>
<div className="border-primary">…</div>
<a className="text-primary">더 보기</a>
<span className="bg-accent text-accent-foreground">진행 중</span>
```

```css
/* app/globals.css — 여기 한 곳 */
:root  { --primary: oklch(0.55 0.15 155); }
.dark  { --primary: oklch(0.72 0.14 155); }
```

- 고칠 곳은 **두 줄**이다
- "브랜드 색"과 "안내 문구 색"이 이름으로 구분돼 있어 **엉뚱한 걸 바꿀 위험이 없다**
- 다크 모드는 `.dark` 값만 같이 바꾼다

작업 견적: **10분.**

</TabItem>
</Tabs>

:::tip[핵심]
테마의 가치는 "예쁘게 만들기"가 아니라 "**바꾸는 비용을 상수로 만들기**"다.
파일이 200개든 2000개든 브랜드 색 교체는 항상 두 줄이다.
:::

**하지만 HTML은 한 글자도 바뀌지 않는다.** `<button class="ui-btn ui-btn--default">저장</button>` 그대로다.

Material Design과 사내 SI 스타일이 이렇게 다른데도 마크업이 같다는 게 요점이다.
바뀐 것은 **이름에 매달린 값**뿐이다.

## 테마가 소유하는 다섯 리소스

"테마 = 색"이라고 생각하면 절반만 관리하게 된다. 실제로는 다섯 종류다.

direction: right

## 왜 "의미"로 이름 붙이는가

토큰에는 두 층이 있다. **이 구분을 놓치면 이름을 붙여도 소용이 없다.**

```d2 layout=elk pad=40 title="원시 토큰이 의미 토큰을 거쳐 컴포넌트로 가야 하고, 컴포넌트가 원시 토큰을 직접 쓰면 안 된다는 것을 보여주는 그림"
direction: down

classes: {
  key: {
    style: {
      fill: "#dbeafe"
      stroke: "#2563eb"
      font-color: "#1e3a8a"
    }
  }
  ok: {
    style: {
      fill: "#dcfce7"
      stroke: "#16a34a"
      font-color: "#14532d"
    }
  }
  bad: {
    style: {
      fill: "#fee2e2"
      stroke: "#dc2626"
      font-color: "#7f1d1d"
    }
  }
  mute: {
    style: {
      fill: "#f1f5f9"
      stroke: "#94a3b8"
      font-color: "#334155"
    }
  }
}

a: "원시 토큰\n--zinc-900: #18181b\n'무슨 색인가'" { class: mute }
b: "의미 토큰\n--primary: var(--zinc-900)\n'무슨 역할인가'" { class: key }
c: "컴포넌트\nclass='bg-primary'" { class: ok }
x: "컴포넌트가 원시 토큰을\n직접 쓰면 ❌" { class: bad }

a -> b
b -> c
a -> x { style.stroke-dash: 3 }
```

| | 원시 토큰 | 의미 토큰 |
|---|---|---|
| 예 | `--zinc-900`, `--blue-500` | `--primary`, `--muted`, `--destructive` |
| 답하는 질문 | 무슨 색인가 | 무슨 역할인가 |
| 개수 | 많다 (팔레트 전체) | 적다 (20개 안팎) |
| 테마마다 | 대체로 같다 | **바뀐다** |
| 컴포넌트가 쓰는 것 | ❌ | ✅ |

:::caution[함정]
**의미 층을 건너뛰는 것**이 가장 흔한 실수다.
`bg-zinc-900`이 컴포넌트에 직접 등장하는 순간, 그 컴포넌트는 테마 밖으로 나간 것이다.
다크 모드에서도 안 바뀌고, 브랜드 교체 때도 안 바뀐다.

**shadcn/ui가 준 `button.tsx`에는 `bg-zinc-900`이 단 한 번도 안 나온다.**
이유가 이것이다.
:::

### 3층 구조는 대개 필요 없다

자료를 찾다 보면 **원시 → 의미 → 컴포넌트** 3층 구조를 보게 된다.
`--button-bg: var(--primary)` 같은 층을 하나 더 두는 것이다.

**대부분의 프로젝트는 2층이면 충분하다.** 3층은 컴포넌트가 수백 개고
팀이 여러 개로 나뉘어 서로 다른 속도로 움직일 때 의미가 생긴다.
처음부터 만들면 관리할 이름만 3배가 된다.

## "같은 컴포넌트"라는 말의 무게

아래 넷은 **완전히 같은 마크업**이다. 값만 다르다.

<ThemeCompare />

여기서 읽어야 할 것은 "예쁘다"가 아니라 —

- 각 열은 **다른 디자인 시스템**이다. Material은 모서리가 크고 보라 계열, 사내 SI는 각지고 진한 파랑
- 그런데 **HTML을 새로 쓰지 않았다.** 컴포넌트를 갈아엎지도 않았다
- 즉 **디자인 시스템 교체 = 토큰 교체**로 만들 수 있다

:::tip[핵심]
이것이 가능한 유일한 조건 —
**컴포넌트 안에 값을 직접 쓰지 않는다.**
이 규칙 하나만 지키면 나머지는 전부 따라온다.
:::

## 리소스를 관리한다는 것

"테마를 만든다"는 말을 실무 동작으로 풀면 이렇다.

| 동작 | 무슨 뜻인가 | 어디서 |
|---|---|---|
| **정의한다** | 리소스마다 이름과 값을 정한다 | `globals.css`의 `:root` |
| **두 벌로 만든다** | 같은 이름에 다크용 값을 하나 더 준다 | `globals.css`의 `.dark` |
| **연결한다** | Tailwind가 `bg-primary` 클래스를 만들게 한다 | `@theme inline` 블록 |
| **강제한다** | 컴포넌트가 이름만 쓰도록 규칙을 세운다 | 코드 리뷰 · 린트 |
| **배포한다** | 다른 앱·팀이 같은 테마를 받게 한다 | 레지스트리 ([11장](/shadcn/11-registry/)) |

**세 번째 "연결한다"가 자주 빠진다.** CSS 변수를 정의하는 것만으로는
`bg-primary` 유틸리티 클래스가 생기지 않는다 — [4장](/shadcn/04-color/#연결하지-않으면-클래스가-안-생긴다)에서 자세히 본다.

## 2장 요약

- 테마는 색 설정이 아니라 **앱의 시각적 결정 전체를 담는 목록**이다
- 가치는 예쁨이 아니라 **바꾸는 비용을 상수로 만드는 것** — 파일이 몇 개든 두 줄
- 테마가 소유하는 리소스 다섯: **색 · 형태 · 글자 · 컴포넌트 · 아이콘/폰트**
- 토큰은 **원시(무슨 색인가) → 의미(무슨 역할인가)** 두 층. 컴포넌트는 **의미 토큰만** 쓴다
- 3층 구조는 대개 필요 없다
- 관리한다는 것 = **정의 → 두 벌 → 연결 → 강제 → 배포**
