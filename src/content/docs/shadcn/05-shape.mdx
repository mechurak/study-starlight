## `--radius` — 하나에서 전부 나온다

shadcn/ui가 `globals.css`에 넣어 주는 것 중 색 다음으로 중요한 게 이 한 줄이다.

```css
:root {
  --radius: 0.625rem;   /* 10px */
}

@theme inline {
  --radius-sm: calc(var(--radius) * 0.6);
  --radius-md: calc(var(--radius) * 0.8);
  --radius-lg: var(--radius);
  --radius-xl: calc(var(--radius) * 1.4);
  --radius-2xl: calc(var(--radius) * 1.8);
  --radius-3xl: calc(var(--radius) * 2.2);
  --radius-4xl: calc(var(--radius) * 2.6);
}
```

컴포넌트는 `rounded-md`, `rounded-lg`만 쓴다.
그래서 **`--radius` 한 줄을 바꾸면 버튼·카드·입력창·모달이 전부 같이 움직인다.**

<ScaleViz kind="radius" />

### 얼마나 달라지는가

같은 마크업을 `--radius`만 바꿔 렌더한 것이다.

<ThemeCompare themes={['corporate', 'shadcn', 'material']} labels={['--radius: 0.125rem', '--radius: 0.625rem', '--radius: 1.25rem']} compact />

- **왼쪽** — 각지다. 금융·엔터프라이즈·관리자 도구의 인상
- **가운데** — shadcn 기본값. 요즘 SaaS의 표준적인 느낌
- **오른쪽** — Material Design. 친근하고 모바일 앱스러움

색도 폰트도 같이 바뀐 프리셋이지만, **모서리만 따라가며 봐도** 인상 차이의 절반 이상이 여기서 온다.

:::tip[핵심]
브랜드 성격을 가장 싸게 표현하는 수단이 `--radius`다. **한 줄이다.**
디자이너가 "좀 더 단단해 보였으면"이라고 하면 먼저 이걸 줄여 본다.
:::

### 왜 계산으로 파생시키는가

`--radius-sm: 4px; --radius-lg: 12px;` 처럼 따로 적으면 안 되나? 된다. 하지만 —

<Tabs>
<TabItem label="따로 적을 때">

```css
--radius-sm: 4px;
--radius-md: 6px;
--radius-lg: 10px;
--radius-xl: 14px;
```

"전체적으로 더 각지게" → **네 줄을 각각 계산해서** 고친다.
비율이 어긋나면 큰 요소만 유난히 둥글어 보인다.

</TabItem>
<TabItem label="파생시킬 때">

```css
--radius: 0.625rem;   /* 이 한 줄만 */
```

"전체적으로 더 각지게" → `0.25rem`으로 바꾼다. **비율이 자동으로 유지된다.**

</TabItem>
</Tabs>

**"결정은 하나, 값은 여러 개"** — 이게 파생의 요점이다.

## 간격 — 스케일로만 쓴다

Tailwind 4는 간격도 기준값 하나에서 파생시킨다.

```css
@theme {
  --spacing: 0.25rem;   /* = 4px, 기본값 */
}
```

`p-1` = 4px, `p-2` = 8px, `p-4` = 16px처럼 번호가 기준값에서 계산된다.
`p-0.5` 같은 반 단계와 `p-px` 같은 예외도 있지만, **한 스케일을 공유한다**는 점이 핵심이다.

<ScaleViz kind="spacing" />

### 스케일이 왜 필요한가

스케일 없이 쓰면 `p-[13px]`, `mt-[7px]`, `gap-[18px]` 같은 값이 섞인다.
개별적으로는 아무 문제 없어 보이는데, **화면 전체로 보면 정렬이 미묘하게 어긋난다.**

- 사람 눈은 4px 단위의 규칙성을 인식한다. 13px과 12px 중 12px이 "정돈돼" 보인다
- 값이 정해져 있으면 **논쟁이 사라진다.** "여기 여백 몇이죠?" → "`gap-4`"
- 나중에 전체 밀도를 조절할 때 `--spacing`만 건드리면 된다

:::caution[함정]
`p-[13px]` 같은 임의값(arbitrary value)이 코드에 늘어나기 시작하면
**스케일이 무너지는 신호**다. 리뷰에서 잡을 항목이다.

정말 필요한 예외는 있다 — 아이콘 광학 정렬, 1px 보정 같은 것.
그럴 땐 **주석으로 이유를 남긴다.**
:::

### 밀도를 다르게 하고 싶을 때

관리자 화면처럼 정보를 빽빽하게 넣어야 하면 `--spacing`을 줄인다.

```css
:root        { --spacing: 0.25rem; }   /* 4px — 기본 */
.dense       { --spacing: 0.2rem;  }   /* 3.2px — 화면당 20% 더 담긴다 */
```

`p-4`가 16px에서 12.8px이 된다. **클래스는 그대로인데 밀도만 바뀐다.**

## 테두리 — 색과 두께

테두리는 색 토큰([4장](/shadcn/04-color/))과 겹치지만, 형태 관점에서 볼 게 하나 있다.

| 토큰 | 쓰이는 곳 |
|---|---|
| `--border` | 카드·구분선 등 **일반 테두리** |
| `--input` | **입력창 테두리** — 일반 테두리보다 진하게 두는 경우가 많다 |
| `--ring` | **포커스 링** — 키보드로 이동했을 때 나오는 테두리 |

**`--ring`이 왜 따로 있나?** 포커스 표시는 접근성 필수 요소다.
키보드만 쓰는 사람에게는 "지금 어디에 있는지"를 알려주는 유일한 단서라
**배경과 확실히 구분되는 색이어야** 한다. 그래서 일반 테두리와 값을 분리한다.

:::caution[함정]
`outline: none`으로 포커스 링을 지우는 코드를 종종 본다.
**키보드 사용자가 화면에서 길을 잃는다.** 디자인이 마음에 안 들면 지우지 말고 `--ring` 값을 바꾼다.
:::

## 그림자 — 고도를 표현한다

그림자는 장식이 아니라 **"이게 저것보다 위에 떠 있다"는 정보**다.

<ScaleViz kind="shadow" />

| 층 | 그림자 | 예 |
|---|---|---|
| 바탕 | 없음 | 페이지 배경 |
| 살짝 뜸 | `shadow-sm` | 카드, 버튼 |
| 떠 있음 | `shadow-md` | 드롭다운, 팝오버 |
| 확실히 위 | `shadow-lg` | 모달, 시트 |

**순서를 지키는 게 규칙의 전부**다. 모달이 카드보다 그림자가 약하면 층위가 뒤집혀 보인다.

:::caution[함정 — 다크 모드의 그림자]
어두운 배경에서는 **검은 그림자만으로 고도를 구분하기 어렵다.**
다크 모드에서는 그림자와 함께 **표면 배경을 살짝 밝게** 하는 쪽이 효과적이다.

```css
:root { --card: oklch(1 0 0);      }   /* 라이트: 배경과 같고 그림자로 띄운다 */
.dark { --card: oklch(0.21 0 0);   }   /* 다크: --background보다 밝게 해서 띄운다 */
```

이래서 `--background`와 `--card`를 [4장](/shadcn/04-color/#자주-헷갈리는-셋)에서 처음부터 구분해 쓰라고 한 것이다.
:::

```d2 layout=elk pad=40 title="radius·spacing·border·shadow 네 토큰이 각각 어떤 유틸리티 클래스로 파생되는지 짝지은 그림"
direction: right

    style: {
      fill: "#f1f5f9"
      stroke: "#94a3b8"
      font-color: "#334155"
    }
  }
}

r: "--radius\n0.625rem" { class: key }
r2: "rounded-sm/md/lg/xl\n계산으로 파생" { class: ok }
s: "--spacing\n0.25rem" { class: key }
s2: "p-1 · p-2 · p-4 …\n4의 배수" { class: ok }
b: --border · --input · --ring { class: mute }
b2: 테두리 · 입력창 · 포커스 { class: mute }
e: shadow-sm → lg { class: mute }
e2: 고도 순서 { class: mute }

r -> r2
s -> s2
b -> b2
e -> e2
```

## 5장 요약

- **`--radius` 한 줄**이 앱 전체 인상의 절반을 결정한다. 나머지 크기는 계산으로 파생된다
- 각지면 엔터프라이즈, 둥글면 친근함 — **브랜드 성격을 가장 싸게 표현하는 수단**
- 간격은 `--spacing` 기준의 **스케일로만** 쓴다. `p-[13px]`가 늘면 스케일이 무너지는 신호
- 밀도 조절은 `--spacing` 하나로 — 클래스는 그대로 두고 화면 밀도만 바꾼다
- **`--ring`은 접근성 요소**다. `outline: none`으로 지우지 않는다
- 그림자는 **고도 정보**다. 순서(카드 < 드롭다운 < 모달)만 지키면 된다
- **다크 모드에서는 검은 그림자만으로 부족하다.** 표면의 밝기 차이도 함께 쓴다
