## 회사가 소유하는 domain

| 용어 | 뜻 | 함께 구분할 것 |
|---|---|---|
| Agent | 회사 안에서 유지되는 서비스 정체성·owner·업무 목적 | 실행 복사본인 Deployment |
| AgentVersion | prompt·knowledge·tool·skill·model·policy와 artifact를 고정한 불변 snapshot | 움직이는 Publication pointer |
| KnowledgeSource | 문서 저장소·업무 DB·upload 묶음의 정체성, owner와 삭제 책임 | 그 시점의 KnowledgeVersion |
| KnowledgeVersion | source revision·ACL·chunking·embedding·index artifact를 고정한 snapshot | runtime memory |
| KnowledgeBinding | AgentVersion이 KnowledgeVersion을 조회하는 filter·citation·principal 전달 계약 | provider index endpoint |
| KnowledgeDeployment | 특정 target에 만들어진 index·retrieval endpoint 상태 | 제품 중립 KnowledgeVersion |
| Tool | MCP server/provider의 회사 정체성 | server가 노출한 개별 ToolCapability |
| ToolCapability | `(toolVersionId, capabilityName)`으로 식별하는 개별 action과 schema·risk | 이름이 같은 다른 server의 action |
| ToolVersion | source·artifact·endpoint fingerprint·discovery schema를 고정한 승인 단위 | 실행 위치인 ToolDeployment |
| ToolBinding | AgentVersion이 사용할 ToolCapability allowlist와 auth mode | 최종 사용자의 action authorization |
| Trigger | request·schedule·event처럼 실행을 시작하는 계기와 principal·retry 계약 | Agent process 상주 방식 |
| Grant | `(agentId, principalKey, role)`의 catalog·관리·invoke 권한 관계 | tool action policy |

## 상태와 실행 위치

| 용어 | 뜻 | 함께 구분할 것 |
|---|---|---|
| DeploymentTarget | zone·architecture·network·isolation 같은 배치 capability 묶음 | 실제 실행 결과인 Deployment |
| Deployment | 승인된 version을 target에 실행한 한 복사본과 desired/observed state | Agent 정체성·Publication |
| providerRef | namespace/name·UID·ARN처럼 provider 안에서만 의미 있는 참조 | 회사 `agentId` |
| AgentVersion state | `DRAFT`부터 `APPROVED`·`RETIRED`까지의 승인 상태 | Deployment health |
| Deployment state | `PENDING`·`PROVISIONING`·`READY`·`FAILED`·`STOPPED` 같은 실행 상태 | catalog 공개 여부 |
| Publication | 사용자에게 공개할 `READY` Deployment와 route를 가리키는 control-plane 객체 | provider-native endpoint |
| publication rollback | active pointer를 직전 `READY` Deployment로 되돌리는 일 | provider resource repair |
| stable endpoint | target이 바뀌어도 consumer가 계속 쓰는 회사 소유 Agent URL | cluster Service·Runtime ARN |

## Runtime과 durability

| 용어 | 뜻 | 함께 구분할 것 |
|---|---|---|
| RuntimeAdapter | 제품 중립 version·target을 workload와 endpoint로 번역하고 상태를 정규화하는 port | PublicationRouter·DurabilityCoordinator |
| RuntimeInvoker | stable API 요청을 provider protocol·session 호출로 번역하는 data-path port | 배포 credential을 쓰는 RuntimeAdapter |
| 맨 Kubernetes 기준선 | adapter가 Deployment·Service·Job을 직접 만드는 온프렘 영가설 | 구성형 engine을 제공하는 kagent |
| kagent | Agent CR·controller·engine으로 Kubernetes Agent lifecycle을 제공하는 후보 runtime | 회사 catalog·ACL |
| AgentCore | AWS가 session별 runtime·격리·scale을 관리하는 후보 target | 온프렘 설치 제품 |
| ExecutionProfile | `none` 또는 durable engine·workflow contract를 workload target과 조합한 실행 계약 | DeploymentTarget |
| durable execution | workflow history로 중단된 step부터 재개하는 보장 | 대화 memory·Pod restart |
| Temporal | 결정 B 재개 시 현재 가정의 잠정 선두인 범용 durable workflow 후보 | 채택된 RuntimeAdapter |
| Dapr Agents | Dapr Workflow 위의 Python durable agent framework 후보 | Agent CR 중심 kagent |

## Identity와 정책

| 용어 | 뜻 | 함께 구분할 것 |
|---|---|---|
| principalKey | OIDC `(iss, sub)` 또는 Entra `(tenantId, objectId)`를 정규화한 사내 불변 ID | email·display name·bare `sub` |
| 관리 권한 | Agent·version·grant·publication을 바꿀 권한 | Agent invocation 권한 |
| invocation 권한 | 현재 principal이 공개된 Agent를 호출할 권한 | tool action 권한 |
| action 권한 | Agent·principal·tool·input을 함께 평가해 업무 action을 허용할지 결정 | prompt의 지시문 |
| PEP | portal API·gateway처럼 policy 결정을 실제 요청에 강제하는 지점 | 단순 UI 숨김 |
| OBO | 현재 사용자의 위임 범위로 downstream을 호출하는 방식 | 공용 workload admin credential |
| effectiveConfigHash | prompt·knowledge·tool·skill·model·policy·execution profile의 실효 조합 hash | `versionId` 하나만 기록하는 trace |
| policy bundle | 공통 guardrail의 독립된 immutable version | 제자리에서 바꾸는 공유 ConfigMap |

## Adapter와 운영

| 용어 | 뜻 | 운영 포인트 |
|---|---|---|
| capability profile | target이 지원하는 protocol·artifact·isolation·network 특성 | 지원하지 않으면 배포 전 `validate`에서 거부 |
| idempotency | 같은 요청을 반복해도 resource와 side effect가 중복되지 않는 성질 | deploymentId·tool action key |
| reconciliation | desired state와 provider observed state를 반복 비교해 수렴시키는 동작 | 일회성 API transaction과 구분 |
| drift | portal DB의 승인 상태와 provider resource가 달라진 상태 | 되돌리기·흡수·격리 정책 |
| normalized status | provider 원문 상태를 공통 Deployment state와 reason code로 번역한 값 | 원문 reason·진단 링크도 보존 |
| contract test | 모든 adapter가 같은 fixture로 지켜야 하는 외부 동작 시험 | provider 기능 목록 비교 |
| data zone | data가 저장·처리·전송될 수 있는 신뢰 경계 | 비용 score보다 먼저 적용하는 hard constraint |
