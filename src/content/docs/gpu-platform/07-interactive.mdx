## 제품 기능을 사용자 여정으로 바꾼다

Backend.AI를 "container를 띄우는 도구"로 보면 마이그레이션 범위를 놓친다. 먼저 실제 사용 여정을
측정한다.

| 사용자 행동 | 현재 Backend.AI가 맡는 것 | 새 플랫폼 후보 |
|---|---|---|
| GPU Notebook 열기 | image·resource preset·session·proxy | JupyterHub·Kubeflow Notebook + profile |
| VSCode·SSH 접속 | session service proxy·인증 | workspace controller·Gateway·SSO |
| 파일 이어 쓰기 | vfolder·quota·mount | PVC·NFS/CSI·object storage·project policy |
| batch 제출 | queue·scheduler·resource group | Kueue + Job·JobSet·Trainer |
| 작은 GPU 요청 | fractional GPU·policy | MIG 우선, time-slicing/MPS는 별도 등급 |
| 사용량 확인 | user·project accounting | DCGM·Pod metadata·chargeback pipeline |
| image 선택 | registry catalog·permission | internal registry·signed runtime catalog |

기능별 일대일 제품 매핑보다 이 표의 각 행을 end-to-end로 통과시키는 것이 중요하다.

모든 연구자에게 YAML을 요구하지 않는다. Kubernetes-native란 사용자가 `kubectl`을 써야 한다는 뜻이
아니라, UI 뒤의 단일 원본이 Kubernetes API라는 뜻이다.

## storage 의미를 보존한다

| 데이터 | 성질 | 권장 바닥 |
|---|---|---|
| 개인 작업 디렉터리 | POSIX·작은 파일·지속 | 사용자별 PVC·NFS/CSI |
| project 공유 dataset | 여러 Pod가 읽음 | RWX file storage 또는 object storage |
| model artifact | version·checksum·대용량 읽기 | object storage·registry·node cache |
| 학습 checkpoint | 크고 주기적·복구 핵심 | 고성능 file/object storage |
| scratch·compile cache | node locality·재생성 가능 | local NVMe·ephemeral volume |

vfolder 하나를 PVC 하나로 단순 치환하지 않는다. 공유·quota·backup·성능·삭제 정책이 같아야 한다.

## fractional GPU를 다시 정의한다

Backend.AI의 fGPU 숫자를 Kubernetes time-slicing replica 수로 그대로 옮기지 않는다.

| 방식 | memory isolation | fault isolation | 적합한 용도 |
|---|---|---|---|
| full GPU | 강함 | workload 단위 | 학습·중요 serving |
| MIG | hardware profile 수준 | 있음 | 작은 serving·개발 session |
| time-slicing | 없음 | 없음 | 신뢰된 가벼운 실험 |
| MPS | 제한적 공유 | 정책 검증 필요 | compute sharing을 검증한 workload |

사용자에게는 `small-a100`, `full-a100` 같은 profile을 보이고 구현을 숨긴다. 다만 isolation 차이는
서비스 등급과 문서에 명시한다.

## Backend.AI 종료 gate

다음 항목이 모두 통과되기 전에는 라이선스를 종료하지 않는다.

- active user와 project가 새 identity·namespace로 매핑됨
- 대표 Notebook·VSCode·batch·multi-node workflow가 성공함
- vfolder data의 checksum·권한·backup이 확인됨
- image catalog와 private registry permission이 이전됨
- quota·queue·priority가 기존 정책과 비교됨
- usage·audit·관리자 장애 대응 경로가 준비됨
- 한 A100 서버를 이전했다가 되돌리는 절차가 rehearsal됨
- 기존 endpoint·SDK 사용자의 cutover 공지가 준비됨

## 공개 Kubernetes backend를 전제로 잡지 않는다

Backend.AI 공식 문서에는 Kubernetes backend 항목이 있지만 공개 내용이 비어 있다. 유료 계약에서
별도 지원되는 구현이 있다면 공급사에 GA 여부·GPU Operator 호환·B300 지원·migration 책임을 서면으로
확인한다. 그렇지 않으면 기존 Backend.AI는 bare-metal 운영을 유지한 채 새 Kubernetes stack과 병행한다.
