## 먼저 바로잡을 네 가지

이 구조를 설계할 때 흔히 어긋나는 경계가 네 곳 있다. 실제 구성으로 옮기기 전에 정확히 잡아 둔다.

1. **Codex의 지침 체인은 세션 시작 때 확정된다.** 프로젝트 루트부터 `cwd`까지만 내려오며,
   [공식 문서가 명시하듯 현재 디렉토리에 도달하면 탐색을 멈춘다](https://learn.chatgpt.com/docs/agent-configuration/agents-md#layer-project-instructions).
   루트에서 시작한 뒤 `apps/web/**`를 수정한다고 해서 `apps/web/AGENTS.md`가 자동 추가되지는 않는다.
2. **Claude Code의 하위 지침은 파일을 읽을 때 lazy load된다.** 공식 문서가 보장하는 표현은
   [“해당 하위 디렉토리의 파일을 읽을 때”](https://code.claude.com/docs/en/memory#how-claudemd-files-load)다.
   따라서 검색 결과만 훑는 모든 경로가 지침 로드를 일으킨다고 가정하지 말고, 수정 전에 대상 범위의
   `AGENTS.md`를 직접 읽으라는 공통 규칙을 둔다.
3. **Claude Code는 `AGENTS.md`를 읽지 않는다.** 읽는 파일명은 `CLAUDE.md`이며, Anthropic도 기존
   `AGENTS.md`를 [`CLAUDE.md`에서 import하는 구성을 직접 권장한다](https://code.claude.com/docs/en/memory#agentsmd).
4. **`@AGENTS.md`는 컨텍스트 절약 장치가 아니다.** import는 파일을 정리하는 문법이고, 내용은 시작 시
   [펼쳐져 함께 로드된다](https://code.claude.com/docs/en/memory#import-additional-files). 현재 공식 문서 기준
   재귀 import는 최대 네 단계이므로, 어댑터는 같은 폴더의 정본 한 개만 가져오게 유지한다.

:::tip[핵심]
두 제품의 자동 탐색이 완전히 같아지게 만들려고 애쓰기보다, **수정 전에 대상 경로의 지침 체인을 직접
확인한다**는 공유 행동 규칙을 둔다. 자동 탐색은 시작을 돕고, 명시적 확인은 두 도구의 차이를 닫는다.
:::

## 두 도구는 어디까지 자동으로 읽는가

| 질문 | Codex | Claude Code |
|---|---|---|
| 기본 프로젝트 파일 | `AGENTS.md` | `CLAUDE.md` 또는 `.claude/CLAUDE.md` |
| 시작 시 프로젝트 탐색 | 프로젝트 루트부터 `cwd`까지 아래로 | `cwd`부터 상위 디렉토리의 파일을 찾아 모두 로드 |
| `cwd` 아래의 중첩 파일 | 자동 탐색하지 않음 | 그 하위 파일을 읽을 때 중첩 `CLAUDE.md`를 lazy load |
| 합치는 방식 | 루트 → 가까운 폴더 순서, 가까운 지침이 우선 | 넓은 범위 → 구체적 범위 순서로 모두 추가; 충돌하면 임의로 하나를 고를 수 있어 모순을 피해야 함 |
| 같은 폴더의 후보 | `AGENTS.override.md` → `AGENTS.md` → 설정한 fallback 중 하나 | `CLAUDE.md` 뒤에 `CLAUDE.local.md` 추가 |
| 시작 시 크기 | 전체 프로젝트 체인 기본 상한 32 KiB | 파일을 전부 컨텍스트에 넣음; 파일당 200줄 미만 권장 |
| 세션 중 재탐색 | 새 실행·TUI 세션에서 체인을 다시 구성 | 중첩 파일은 작업 중 발견; `/compact` 뒤 루트 파일만 자동 재주입 |
| 확인 방법 | 대상 폴더에서 활성 지침을 요약하도록 실행 | `/context`의 Memory files, 필요하면 `InstructionsLoaded` hook |

Codex의 탐색 순서·한 폴더당 한 파일·32 KiB 기본 상한은
[OpenAI의 `AGENTS.md` 공식 문서](https://learn.chatgpt.com/docs/agent-configuration/agents-md#how-codex-discovers-guidance)에,
Claude Code의 전체 로딩 순서와 `/compact` 뒤 중첩 파일 재로딩 조건은
[Anthropic의 memory 문서](https://code.claude.com/docs/en/memory#instructions-seem-lost-after-compact)에 있다.

여기서 공동 설계를 좌우하는 차이는 하나다. Codex는 가까운 파일로 앞선 규칙을 **override할 수 있지만**,
Claude Code는 여러 파일을 **additive context**로 읽고 충돌하면 어느 쪽을 따를지 보장하지 않는다.
따라서 하위 파일을 “상위 내용을 부정하는 문서”로 쓰지 말고, **그 범위에만 필요한 차이와 더 구체적인
명령**으로 쓴다.

Claude Code에는 경로 조건부 지침을 위한 전용 장치도 있다. `.claude/rules/`의 파일에
[`paths` frontmatter](https://code.claude.com/docs/en/memory#path-specific-rules)를 두면 그 glob에 맞는
파일을 다룰 때만 규칙이 로드된다. 다만 Codex는 이 디렉토리를 읽지 않으므로, 두 도구가 공유할 규칙의
정본은 범위별 `AGENTS.md`로 유지하고 rules는 Claude 전용 보정에만 쓴다.

## 목표 monorepo 구조

단일 package 저장소라면 루트의 두 파일만 있으면 된다. 여러 앱과 공유 package가 있다면 규칙이 실제로
달라지는 경계에만 파일 쌍을 추가한다.

<FileTree>

- my-workspace/
  - **AGENTS.md** 저장소 전체 공유 규칙 + 하위 지침 확인 규칙
  - **CLAUDE.md** `@AGENTS.md` + 최소한의 Claude 전용 보정
  - CLAUDE.local.md 개인용 로컬 메모 — gitignore
  - docs/ 긴 설명의 정본
    - architecture.md 시스템 구조와 경계
    - verification.md 변경 종류별 검증 절차
  - scripts/
    - check-agent-instructions.mjs 파일 쌍·import·중복을 검사하는 CI script
  - apps/
    - web/
      - **AGENTS.md** web에서만 다른 규칙과 명령
      - **CLAUDE.md** `@AGENTS.md`
      - src/
    - api/
      - **AGENTS.md** API에서만 다른 규칙과 명령
      - **CLAUDE.md** `@AGENTS.md`
      - src/
  - packages/
    - ui/
      - **AGENTS.md** UI package 전용 규칙
      - **CLAUDE.md** `@AGENTS.md`
      - src/

</FileTree>

모든 폴더에 파일 쌍을 두지는 않는다. `apps/web/src/components/`가 `apps/web/`와 같은 규칙을 쓴다면
중첩 파일이 필요 없다. **명령·소유권·검증·금지사항 중 하나가 실제로 달라지는 경계**에만 추가한다.

`AGENTS.override.md`는 이 공동 구조의 정본으로 쓰지 않는 편이 낫다. Codex는 같은 폴더에서 이것을
`AGENTS.md`보다 먼저 골라 나머지를 무시하지만, `CLAUDE.md`의 `@AGENTS.md`는 그 override를 알지 못한다.
Codex 개인 환경의 임시 override에는 쓸 수 있어도, 두 도구가 공유할 committed 규칙에는 파일명이
고정된 `AGENTS.md`가 예측 가능하다.

## 루트 파일은 지도와 공통 계약이다

루트 `AGENTS.md`에는 저장소 전체에서 언제나 필요한 행동만 둔다. 특히 첫 절이 Codex의 하향 탐색 차이를
메우는 장치다.

```md title="AGENTS.md"
# Repository instructions

## Instruction discovery

- Before starting, identify every target path the task may modify.
- For each target, read every `AGENTS.md` from the repository root down to
  the target directory, in that order. The closest file supplies the most
  specific rules.
- If the task expands into another app or package, repeat this check before
  editing there.

## Repository map

- `apps/web/`: customer-facing web app.
- `apps/api/`: public API and database migrations.
- `packages/ui/`: shared UI primitives.
- `docs/architecture.md`: system boundaries and dependency direction.
- `docs/verification.md`: checks required for each kind of change.

## Working agreement

- Use `pnpm`; do not generate an npm or Yarn lockfile.
- Read the relevant architecture document before changing a public boundary.
- Preserve user changes outside the requested scope.
- Do not commit, push, deploy, or add a production dependency unless asked.

## Validation

- Run the smallest relevant package check while iterating.
- Before handing off, run `pnpm check` from the repository root.
- Report which checks ran and any check that could not run.
```

실제 저장소에서는 map을 모든 디렉토리 목록으로 만들지 않는다. “이 작업이면 어디를 먼저 읽는가”를
결정하는 entry point만 둔다. OpenAI도 대규모 Codex 운영 사례에서 거대한 `AGENTS.md` 대신 짧은 지도와
구조화된 `docs/`를 정본으로 두었다고 설명한다
([Harness engineering](https://openai.com/index/harness-engineering/)).

루트 `CLAUDE.md`는 기본적으로 한 줄이면 된다.

```md title="CLAUDE.md"
@AGENTS.md
```

Anthropic 문서는 Claude 전용 내용을 더할 계획이 없다면 `ln -s AGENTS.md CLAUDE.md` symlink도 안내한다.
다만 Windows에서는 symlink 생성에 관리자 권한이나 개발자 모드가 필요하므로, 팀 환경이 섞여 있다면
import 한 줄이 더 이식 가능하다.

`/compact` 뒤에도 여러 하위 package 작업을 계속하는 경우를 자주 겪는다면 도구 차이를 보정하는 한 절만
추가할 수 있다. 공유 코딩 규칙을 여기에 다시 쓰지는 않는다.

```md title="CLAUDE.md — 선택 사항"
@AGENTS.md

## Claude Code only

After `/compact`, reread the `AGENTS.md` chain for every active target path
before continuing the edits.
```

Anthropic 문서에 따르면 프로젝트 루트 `CLAUDE.md`는 `/compact` 뒤 다시 주입되지만 중첩 파일은 다음 파일
읽기 전까지 자동으로 돌아오지 않는다
([공식 설명](https://code.claude.com/docs/en/memory#instructions-seem-lost-after-compact)). 이 보정은
제품 차이에만 관한 것이므로 얇은 어댑터의 역할을 넘지 않는다.

## 하위 파일은 상위 규칙의 복사본이 아니다

`apps/web/AGENTS.md`에는 web 범위에서 달라지는 것만 둔다. 루트의 공통 금지·작업 방식·전체 검사 명령을
복사하면 다음 수정부터 두 벌이 어긋난다.

```md title="apps/web/AGENTS.md"
# Web app instructions

## Scope

These rules apply to files under `apps/web/`.

## Local conventions

- Reuse components from `packages/ui/` before creating an app-local primitive.
- Server-only modules stay under `src/server/`; never import them into client code.
- User-visible copy must use the existing i18n keys.

## Validation

- Run `pnpm --filter web test` for behavior changes.
- Run `pnpm --filter web typecheck` for TypeScript changes.
- Check the changed route at 390 px and 1280 px for layout changes.
```

같은 폴더의 adapter는 다시 한 줄이다.

```md title="apps/web/CLAUDE.md"
@AGENTS.md
```

:::caution[충돌을 override로 풀지 않는다]
예를 들어 루트에는 “모든 package가 Jest를 쓴다”, web에는 “Vitest를 쓴다”라고 적지 않는다. 루트는
“package별 test 명령은 가까운 `AGENTS.md`를 따른다”고 쓰고, web에 정확한 명령을 둔다. Codex의 우선순위와
Claude Code의 additive loading 양쪽에서 모순 없이 읽힌다.
:::

## 실행 위치를 작업 범위에 맞춘다

하위 지침 확인 규칙이 안전망이지만, 한 package만 고치는 일은 애초에 그 package를 `cwd`로 시작하는 것이
가장 단순하다. 그러면 두 도구 모두 루트와 package 범위의 시작 지침을 갖는다.

<Tabs>
<TabItem label="한 package 작업">

```bash
# Codex
codex --cd apps/web

# Claude Code
cd apps/web
claude
```

Codex는 프로젝트 루트 → `apps/web` 체인을 만들고, Claude Code는 `apps/web` → 상위 경로의 파일을 찾아
읽는다. 실행 후 바로 활성 지침을 확인하면 설정 오류를 작업 전에 잡을 수 있다.

</TabItem>
<TabItem label="여러 package 작업">

```bash
# repository root
codex
# 또는
claude
```

프롬프트에 대상 범위를 먼저 적는다. 예: “`apps/api`의 응답 계약과 `apps/web` 소비 코드를 함께 바꾼다.
두 경로의 지침 체인을 읽고 계획을 세워라.” 루트 `AGENTS.md`의 discovery 규칙에 따라 각 package 파일을
직접 읽은 뒤 수정한다.

</TabItem>
</Tabs>

Codex에서 중첩 로딩을 확인하려면 공식 문서의 예시처럼 다음 명령을 쓸 수 있다.

```bash
codex --cd apps/web --ask-for-approval never \
  "Show which instruction files are active."
```

Claude Code에서는 `/context`의 **Memory files**에서 실제 로드 목록을 본다. `/memory`는 파일 위치를
편집하는 입구이고, 실제 현재 컨텍스트 확인은 `/context`라는 구분도
[공식 troubleshooting](https://code.claude.com/docs/en/memory#claude-isnt-following-my-claudemd)에 명시되어 있다.

## 지침에는 행동만, 설명은 연결만 둔다

좋은 기준은 “이 문장이 없으면 에이전트가 같은 실수를 반복하는가”다. 코드에서 쉽게 알아낼 수 있는 사실을
매 세션 컨텍스트에 복제하지 않는다.

| `AGENTS.md`에 둔다 | 별도 문서·다른 장치로 보낸다 |
|---|---|
| 정확한 build·test·lint 명령 | 긴 설치·배포·장애 복구 절차 → `docs/` 또는 skill |
| 수정 전 반드시 읽을 정본 경로 | 전체 디렉토리 tree·dependency 목록 → 코드와 manifest |
| 생성 파일·migration·보안 경계의 금지사항 | 제품·도메인 배경 설명 → architecture 문서 |
| package별 naming·dependency 방향 | formatter가 판정할 공백·정렬 규칙 → formatter와 CI |
| 변경 종류별 최소 검증과 완료 조건 | 반드시 차단해야 하는 위험 행동 → hook·권한·CI |
| 요청 없이 commit·push·deploy하지 않는 작업 경계 | 가끔만 쓰는 긴 checklist → skill 또는 runbook |

Claude Code 공식 문서는 구체적이고 검증 가능한 문장을 쓰고 파일당 200줄 아래를 목표로 하라고 권한다
([Write effective instructions](https://code.claude.com/docs/en/memory#write-effective-instructions)). Codex 쪽에는
파일당 권장 줄 수 대신 전체 프로젝트 지침 체인의 **32 KiB 기본 상한**이 있다. 두 조건을 함께 보면
“상한을 늘리기”보다 “루트는 지도, 하위는 차이, 긴 내용은 링크”가 먼저다.

프롬프트 지침은 강제가 아니다. Anthropic도 “매 편집 뒤 실행”처럼 반드시 같은 시점에 일어나야 하는 것은
[hook으로 옮기라고 설명한다](https://code.claude.com/docs/en/memory#claude-isnt-following-my-claudemd).
두 도구가 함께 쓰는 저장소에서는 공통 불변 조건을 formatter·test·CI에 두는 것이 가장 이식 가능하다.

## 운영 체크리스트

처음 만들 때보다 구조가 자란 뒤의 drift를 잡는 장치가 중요하다.

- [ ] 공유 규칙은 같은 범위의 `AGENTS.md` 한 곳에만 있다.
- [ ] committed `AGENTS.md`마다 같은 폴더의 `CLAUDE.md`가 `@AGENTS.md`를 import한다.
- [ ] 루트 지침이 **대상 경로별 지침 체인을 수정 전에 직접 읽으라**고 요구한다.
- [ ] 하위 지침은 상위의 복사가 아니라 그 범위의 차이만 적는다.
- [ ] `AGENTS.override.md`를 두 도구의 공유 정본으로 쓰지 않는다.
- [ ] 긴 구조·절차·reference는 `docs/`로 옮기고 지침에는 읽을 조건과 링크만 둔다.
- [ ] formatting·generated-file 검사처럼 판정 가능한 규칙은 CI가 검사한다.
- [ ] 단일 package 작업은 그 package를 `cwd`로 시작한다.
- [ ] 여러 package 작업은 대상 package를 프롬프트에 열거하고 각 지침 체인을 확인한다.
- [ ] Codex는 대상 `--cd`에서 활성 지침을 확인하고, Claude Code는 `/context`에서 Memory files를 확인한다.
- [ ] Claude Code에서 `/compact` 뒤 작업을 계속하면 활성 하위 지침을 다시 읽는다.

adapter drift도 CI로 잡을 수 있다. `scripts/check-agent-instructions.mjs` 같은 작은 검사를 만들어 다음 세 가지를
검증하면 충분하다.

1. `node_modules`·build output을 제외한 모든 committed `AGENTS.md`를 찾는다.
2. 같은 폴더에 `CLAUDE.md`가 있고 실제 import 줄 `@AGENTS.md`가 있는지 확인한다.
3. adapter에 허용된 Claude 전용 절 외에 공유 명령·규칙이 중복되지 않았는지 검사한다.

마지막 항목은 처음에는 review checklist로 시작해도 된다. 반복해서 drift가 생길 때만 구조화된 marker나
script 검사로 강화한다. 지침 관리 자체가 복잡한 프레임워크가 되면 짧은 지도라는 목적을 잃는다.

## 이 장의 결론

- 제안한 네 원칙 — **범위별 `AGENTS.md` 정본, 얇은 `CLAUDE.md`, 루트의 하위 규칙 확인, 행동 규칙만 유지** — 을 그대로 기본안으로 쓸 수 있다.
- Codex는 시작 시 프로젝트 루트부터 `cwd`까지만 읽으므로, 루트 실행에서 하위 package를 만질 때는 대상 `AGENTS.md`를 직접 읽게 해야 한다.
- Claude Code는 하위 파일을 읽을 때 중첩 지침을 lazy load하지만, 그 동작만 믿지 않고 같은 명시적 확인 규칙을 공유한다.
- 하위 파일은 override 경쟁이 아니라 **범위별 delta**로 작성해야 Codex의 우선순위와 Claude Code의 additive loading을 함께 만족한다.
- 설명은 docs, 가끔 쓰는 workflow는 skill, 반드시 지켜야 하는 것은 CI·hook에 두고 지침 파일은 작업 지도로 남긴다.
