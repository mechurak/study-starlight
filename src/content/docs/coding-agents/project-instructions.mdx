Git·Markdown을 아는 독자가 단일 저장소에 처음 적용하는 구성이 기본이다.

## 같은 규칙을 두 파일에 복사하면 어긋난다

예를 들어 검사 명령을 `npm test`에서 `pnpm check`로 바꿨는데 `CLAUDE.md`만 고쳤다고 하자.
어느 도구로 시작했느냐에 따라 다른 검사를 실행한다. 지침이 없는 것이 아니라 정본이 둘인 문제다.
이 덱은 다음 세 역할로 나누는 운영안을 권한다. 모든 도구가 요구하는 공식 파일 구조라는 뜻은 아니다.

| 역할 | 위치 | 맡는 일 |
|---|---|---|
| 공유 행동 규칙 | `AGENTS.md` | 수정 전 읽을 문서, 작업 범위, 실제 검사 명령 |
| 도구별 연결 | `CLAUDE.md` | `@AGENTS.md` import |
| 실행 결과 판정 | 검사 스크립트·CI | 문법·링크·테스트 등 기계가 확인할 조건 |

지침은 행동을 유도하지만 검사 실행이나 성공을 보장하지 않는다. 검사가 통과해도 설명의 정확성과
이해 가능성은 별도로 리뷰해야 한다. 이 사이트에서는 `docs/content-authoring.md`와
`docs/verification.md`가 각각 의미 리뷰와 기술 검증의 정본이다.

## 루트 파일은 지도와 공통 계약이다

다음은 **새 학습 노트 저장소에서 시작할 최소 예시**다. 기존 AGENTS를 통째로 덮어쓰지 말고
실제 파일·명령에 맞춰 병합한다. 이 사이트의 완전한 계약은 루트 `AGENTS.md`에 있다.

```md title="AGENTS.md — 최소 예시"
# 작업 규칙

- 구조·명령은 README.md, 콘텐츠 작성은 docs/content-authoring.md를 읽는다.
- 수정할 덱의 _baseline.md를 먼저 읽는다.
- 대상 경로에 하위 AGENTS.md가 있으면 수정 전에 읽는다.
- 사용자 변경을 보존하고 요청 범위 안에서 편집·검증·오류 수정까지 마친다.
- 사이트 콘텐츠·코드·설정을 바꿨으면 pnpm check를 실행한다.
- 지침·계획만 바꿨으면 diff와 참조 경로를 확인한다.
- 필수 검사가 통과하면 끝낸다. 새 변경·실패·미해결 문제가 있을 때만 반복한다.
- 커밋·푸시·배포는 요청받았을 때만 한다.
```

같은 폴더의 어댑터는 한 줄이다.

```md title="CLAUDE.md"
@AGENTS.md
```

Claude Code는 `AGENTS.md`를 기본 지침 파일명으로 자동 탐색하지 않지만,
[`CLAUDE.md`에서 import하는 방식](https://code.claude.com/docs/en/memory#agentsmd)을 지원한다.
import는 내용도 컨텍스트에 넣는다. 파일이 짧아 보인다고 컨텍스트 사용량이 줄어드는 것은 아니다.

## 지침에는 행동만, 설명은 연결만 둔다

“좋은 문서를 써라”는 결과를 판정하기 어렵다. “예제에 입력·예상 결과·복구 방법을 적고 실행해라”는
빠진 부분을 확인할 수 있다. 긴 설명까지 루트에 넣기보다 **언제 어디를 읽는지** 연결한다.

| 반복해서 필요한 것 | 둘 곳 |
|---|---|
| 대상 덱 baseline을 먼저 읽는다 | AGENTS |
| 독자·질문·근거·예제를 리뷰하는 상세 순서 | 작성 지침 |
| 이번 덱을 어떻게 분할하기로 했는가 | 해당 작업 계획 |
| 모든 내부 링크가 존재해야 한다 | 링크 검사 스크립트 |
| 배포 환경을 설정하는 긴 절차 | 배포 문서 |

조건 없이 모든 문서를 읽게 하면 작은 수정에도 배포·실습 설명이 섞인다. 반대로 경로만 나열하면
언제 필요한지 모른다. “D2를 추가·수정할 때 D2 지침을 읽는다”처럼 선택 조건과 경로를 함께 둔다.
가끔 반복하는 절차를 skill로 옮길 때도 같은 기준으로 선택 범위를 좁힌다.

## 작은 작업으로 지침 변경을 비교한다

지침을 줄였다는 사실만으로 개선을 판정하지 않는다. 같은 시작 파일에서 오타 수정·새 페이지 추가·
링크 오류 수정 중 필요한 표본을 골라 **놓친 요구, 불필요한 승인 질문, 읽은 문서, 검사 반복**을 본다.
모델 이름이 바뀌었다고 파일 탐색이나 도구 권한까지 바뀌었다고 가정하지 않는다.
제품별 동작은 [지침 탐색](/coding-agents/instruction-discovery/)에서 따로 확인한다.

이 사이트에서 직접 해 볼 확인은 다음과 같다.

```bash
cat CLAUDE.md
git diff -- AGENTS.md CLAUDE.md
```

첫 명령의 예상 결과는 `@AGENTS.md` 한 줄이다. 두 번째에서는 같은 규칙이 두 파일에 중복되지
않는지 확인한다. 이 확인은 파일 구성 검사이며 에이전트가 실제로 로드했다는 증거는 아니다.
임시로 바꿨다면 실습 전 사본을 되돌리고, 기존 사용자 변경까지 지우는 일괄 reset은 하지 않는다.

## 이해 확인

검사 명령이 바뀌었을 때 어디를 고쳐야 할까? 실제 명령은 `package.json`, 에이전트가 알아야 할
작업 계약은 AGENTS 또는 그 계약이 가리키는 검증 지침을 고친다. CLAUDE 어댑터에는 복제하지 않는다.
명령 문자열을 검색해 설명과 실제 실행이 맞는지도 확인해야 한다.
