Claude Code와 Codex는 같은 코드를 고치지만, 저장소 지침을 찾는 방식은 같지 않다. 이 차이를 모르고
`AGENTS.md`와 `CLAUDE.md`에 같은 규칙을 복사하면 둘은 곧 어긋난다. 반대로 한 파일만 두면 어느 한쪽이
하위 package 규칙을 놓칠 수 있다.

이 덱은 그런 경계에서 출발한다. 첫 장에서는 monorepo까지 견디는 지침 계층을 만들고, 둘째 장에서는
GitHub 이슈 대신 `docs/batches/`에 목표·계획·상태·검증을 남기며 AI와 한 마일스톤씩 개발하는
프로세스를 세운다. 이때 PRD는 현재 제품 요구, batch는 변경 과정과 증거로 분리한다. 이후 실제로
반복해서 쓸 만한 컨텍스트·검증 패턴을 한 장씩 보탠다.

## 이 덱의 기본 관점

지침 파일은 설명서가 아니라 **작업 입구의 표지판**이다. 항상 알아야 할 행동 규칙과 정확한 명령만
짧게 두고, 아키텍처와 긴 절차는 별도 문서로 연결한다. 반드시 지켜야 하는 포맷·검사·금지는 프롬프트에만
기대지 않고 CI나 hook으로 옮긴다.

이 원칙은 OpenAI가 실제 Codex 운영에서 `AGENTS.md`를 거대한 백과사전 대신 짧은 지도처럼 쓴다는
[harness engineering 사례](https://openai.com/index/harness-engineering/)와, Claude Code가 `CLAUDE.md`를
200줄 아래로 유지하고 세부 절차는 path-scoped rule이나 skill로 옮기라고 하는
[Anthropic 공식 가이드](https://code.claude.com/docs/en/memory#write-effective-instructions)에 공통으로 나타난다.
