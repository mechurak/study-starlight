<Thesis>반복 규칙은 공유 지침에 두고, 요청에는 작업 목표를 쓰며 계획 문서는 명시적으로 요청할 때 만든다</Thesis>

에이전트에게 같은 규칙을 매번 설명하거나, 다음 세션에서 이미 한 작업을 반복하는 문제에서 출발한다.
Git·Markdown·기본 명령 실행을 아는 독자가 **단일 저장소의 지침을 구성하고, 작은 덱을 맡기고,
결과를 리뷰한 뒤 재개할 수 있는 것**이 목표다. 특정 모델의 성능 비교나 API 개발은 다루지 않는다.

기본 경로는 공유 지침 → 제품별 탐색 → 계획 문서의 생성·관리 기준 → 실행과 재개다. 여러 앱을 관리할 때만
monorepo 심화를 읽는다. 파일 이름과 문서 체계는 이 덱의 운영안이며 제품의 의무 규격이 아니다.
두 CLI는 학습 사이트 빌드의 필수 의존성이 아니고, 사용할 때만 각 제품의 설치·계정 준비가 필요하다.

## 읽은 뒤 확인할 것

공유 규칙의 편집 지점, 현재 작업의 실행 범위, 완료를 뒷받침하는 증거를 각각 가리킬 수 있어야 한다.
예를 들어 “검사가 통과했다”와 “독자가 예제를 실행해 원리를 확인할 수 있다”는 다른 조건이다.
기술 검사와 의미 리뷰를 모두 수행하고 실제 확인한 범위만 보고한다.

2026-09-18에 본문의 공식 근거와 이 저장소의 파일을 대조했다. 도구별 별도 세션의 자동 로딩을
실측한 결과는 아니며, 실제 로드 확인 방법은 지침 탐색 페이지에 있다.
2026-09-19에는 이 저장소의 계획 생성·파일명·검색 규칙과 일반 요청 예시를 갱신했다.
