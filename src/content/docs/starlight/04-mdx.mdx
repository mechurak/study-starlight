## 마크다운의 한계에서 출발한다

순수 마크다운으로 표현할 수 있는 구조는 제목·목록·표·코드·인용이 전부다.
문서를 쓰다 보면 곧 부족해진다 — 순서 있는 절차를 눈에 띄게, 두 갈래 비교를 탭으로,
분류 개요를 카드로 만들고 싶어진다.

전통적 탈출구는 마크다운에 raw HTML을 박는 것이었다. 되긴 되지만 —

- 같은 패턴을 페이지마다 복붙하게 되고, 고칠 때 전부 찾아 고쳐야 한다
- 스타일이 페이지마다 조금씩 어긋난다 — 사이트의 일관성이 무너진다
- 마크다운의 장점인 **평문 가독성**이 사라진다

MDX의 답은 컴포넌트다 — 패턴을 컴포넌트로 한 번 정의하고, 본문에는 태그 하나만 남긴다.
"raw HTML을 본문에 쓰지 않는다"는 이 레포의 [콘텐츠 작성 규칙](https://github.com/mechurak/study-starlight/blob/main/docs/content-authoring.md)은 취향이 아니라
**MDX를 쓰는 이유 그 자체**다.

## MDX 문서의 해부

이 덱의 아무 장이나 열면 구조가 똑같다 —

```mdx
---
title: "4. MDX — 마크다운에 컴포넌트를"    # ① 프론트매터 — 페이지 속성
description: "..."
---

import { LinkCard } from '@astrojs/starlight/components';   // ② import
import TermIntro from '../../../components/docs/TermIntro.astro';

일반 마크다운 본문이 흐르다가...                              // ③ 마크다운

<TermIntro terms={[ ... ]} />                                 // ④ 컴포넌트

다시 마크다운으로 돌아온다. **강조**도 [링크](/)도 그대로다.
```

핵심 관점 하나 — 이 파일은 문서가 아니라 **컴파일되는 소스 코드**다.
import가 틀리면, 태그를 안 닫으면, 중괄호가 짝이 안 맞으면 빌드가 실패한다.
귀찮음이 아니라 보증이다 — 위키에서는 깨진 문법이 조용히 이상하게 렌더되지만,
MDX에서는 **배포 전에 에러로 잡힌다.**

## 변환 파이프라인 — 에러가 나는 층 읽기

`.mdx` 하나가 HTML이 되기까지 —

```d2 title="MDX 파일이 remark 파싱과 rehype 변환, JSX 평가를 차례로 거쳐 정적 HTML이 되는 변환 파이프라인"
direction: down

classes: {
  key: {
    style: {
      fill: "#dbeafe"
      stroke: "#2563eb"
      font-color: "#1e3a8a"
    }
  }
  mute: {
    style: {
      fill: "#f1f5f9"
      stroke: "#94a3b8"
      font-color: "#334155"
    }
  }
  ok: {
    style: {
      fill: "#dcfce7"
      stroke: "#16a34a"
      font-color: "#14532d"
    }
  }
}

src: "*.mdx" { class: key }
remark: "remark\n마크다운 파싱\nD2 펜스를 여기서 가로챈다" { class: mute }
rehype: "rehype\nHTML 트리 변환\n제목 → 앵커 id 생성" { class: mute }
jsx: "JSX 평가\nimport 해석 · 컴포넌트 렌더" { class: mute }
out: "정적 HTML" { class: ok }

src -> remark
remark -> rehype
rehype -> jsx
jsx -> out
```

이 그림의 실용적 가치는 **에러 메시지의 소속 파악**이다 —

| 에러의 낌새 | 층 | 흔한 원인 |
|---|---|---|
| `Could not parse expression` · acorn 언급 | JSX 평가 | 본문의 중괄호 `{`, 안 닫힌 태그 |
| `Cannot find module` | import | 컴포넌트 상대 경로 오타 |
| 프론트매터 필드 에러 | 콘텐츠 컬렉션 (2장) | `title` 누락, 필드명 오타 |
| 에러 없이 **모양만 이상** | 렌더 결과 | 강조 깨짐 · 들여쓰기 코드 블록 — 아래 두 절 |

가장 위험한 것은 마지막 줄이다 — 빌드가 통과하는 문제는 아래에서 따로 다룬다.

## 마크다운과 다른 점 — 함정 네 개

MDX는 마크다운의 초집합이 아니다. **몇 가지 평문이 문법이 되어 버린다.**

### 중괄호는 표현식이다

본문의 `{`부터 MDX는 JavaScript 표현식을 기대한다. `{옵션}` 같은 표기를 평문으로 쓰면
파싱 에러이거나, 더 나쁘게는 조용히 평가된다. **백틱으로 감싸면**(`{옵션}`) 코드 스팬은
JSX 해석을 받지 않아 안전하다.

### HTML 주석이 없다

`<!-- -->`는 MDX에서 에러다. 주석은 JSX 방식으로 쓴다 —

```mdx
{/* 이건 렌더되지 않는 주석 */}
```

### 컴포넌트 태그 안의 마크다운은 들여쓰지 않는다

태그 자식을 예쁘게 2칸 이상 들여쓰면, 마크다운 파서가 그 줄을 **코드 블록으로**
먹을 수 있다 (4칸부터 확정). 이 레포의 규칙 — `<Card>`·`<TabItem>` 자식은 태그와 내용
전부 **0칸**에 두고 빈 줄로 띄운다. 예외는 `<Steps>` 안의 번호 목록 하나다
(목록 항목에 딸린 코드 블록은 3칸 — 목록 문법이 요구하는 들여쓰기라서).

### 여는 꺾쇠도 문법이다

`<`로 시작하는 단어(`<something>`)는 태그로 해석된다. 제네릭·플레이스홀더 표기는
백틱 안에 넣는다 — `<덱이름>`처럼.

## 한글 문서의 `**` 함정 — 빌드가 안 잡는 그 문제

이 레포에서 가장 자주 밟는 지뢰라 절 하나를 통째로 쓴다.
CommonMark의 강조 규칙에서 닫는 `**`는 **"단어의 끝" 위치여야** 강조를 닫을 수 있다.
그런데 닫는 `**` 바로 앞이 따옴표·괄호·`%`·백틱 같은 문장부호이고 **뒤에 한글 조사가
바로 붙으면**, 그 위치는 "단어 중간"으로 판정되어 강조가 안 닫힌다 —
결과: `**` 두 글자가 **화면에 그대로 보인다.** 빌드는 통과한다.

| 깨지는 표기 | 고치는 법 | 요령 |
|---|---|---|
| `**"조회 → 해결"**의` | `"**조회 → 해결**"의` | 따옴표·괄호를 굵게 **밖**으로 |
| `**커리큘럼의 25%**가` | `**커리큘럼의 25%가**` | 조사를 굵게 **안**으로 |
| `` **`get all`**이다 `` | `` `get all`이다 `` | 코드 서식이 이미 강조다 — `**`를 뺀다 |

:::caution[함정]
이 문제는 눈으로 훑어서 못 잡는다 — **산출물로 판정한다.** `pnpm build` 후:

```bash
grep -rho '\*\*[^<*]\{0,45\}' dist --include=index.html | sort -u
```

코드 블록 안에 남는 것(글롭 `/**`, JS 주석)은 정상이니 무시한다.
:::

## 이 레포의 MDX 운용

- **전 페이지가 처음부터 `.mdx`다.** `.md`로 시작했다가 컴포넌트가 필요해지면 확장자를
  바꾸고 링크를 걱정하는 일을 없앴다 — slug는 확장자와 무관하므로(3장) 비용도 없다
- `@astrojs/mdx`는 Starlight의 전이 의존성이라 **별도 설치가 없다** — package.json에 안 보여도 정상
- 컴포넌트 import는 두 종류뿐이다 — 내장은 `@astrojs/starlight/components`에서,
  커스텀은 역할에 따라 `../../../components/docs/` 또는 `../../../components/demos/` 상대 경로로

## 4장 요약

- MDX = 마크다운 + import + 컴포넌트. **컴파일되는 소스**라서 빌드가 문법을 보증한다
- 파이프라인은 remark → rehype → JSX 평가 — **에러 메시지가 어느 층 것인지**부터 읽는다
- 평문이 문법이 되는 지점 네 곳: 중괄호 · HTML 주석 · 태그 안 들여쓰기 · 여는 꺾쇠 — 전부 **백틱과 0칸 들여쓰기**로 피한다
- 닫는 `**` 앞 문장부호 + 뒤 조사 = **강조가 안 닫힌다.** 빌드가 통과하니 grep으로 산출물을 판정한다
- 이 레포는 전 페이지 `.mdx` — 확장자 고민을 없앤 선택
