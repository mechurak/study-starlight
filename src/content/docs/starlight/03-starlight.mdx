## Starlight가 주는 것

Starlight는 "문서 사이트라면 어차피 다 만들게 되는 것"을 전부 내장한 패키지다.

| 영역 | 내장된 것 | 우리가 하는 일 |
|---|---|---|
| 라우팅 | 파일 경로 → URL 자동 매핑 | 파일을 만들 뿐 |
| 탐색 | 사이드바 · 이전/다음 링크 · 우측 TOC | 페이지에 그룹·순서 선언 |
| 검색 | Pagefind 정적 인덱스 (8장) | 없음 — 빌드가 만든다 |
| 외관 | 다크모드 · 반응형 · 테마 CSS 변수 | 원하면 덮어쓰기 |
| i18n | 로케일 라우팅 · UI 문자열 번역 | `locales` 선언 |
| SEO | canonical · sitemap · Open Graph 태그 | `site`와 `description` 채우기 |
| 접근성 | 키보드 탐색 · 스킵 링크 · ARIA | 없음 |

이 표의 왼쪽을 직접 조립해 본 적이 있다면 이 목록이 얼마나 큰 절약인지 안다.
없다면 이렇게 기억하면 된다 — **우리가 만드는 것은 콘텐츠와 구조 선언뿐**이고,
나머지는 전부 프레임워크의 일이다(0장의 3층 모델).

## 파일이 곧 페이지다

`src/content/docs/` 아래의 파일 하나가 페이지 하나다. 이 레포의 실제 구조 —

<FileTree>
- astro.config.mjs 사이트 설정 + Starlight 연결
- src/
  - data/
    - **catalog.mjs** 전역 category · tag 어휘
    - **load-decks.mjs** 덱 폴더와 MDX를 읽어 사이드바 · 랜딩 데이터를 파생
    - decks.mjs 기존 import용 re-export
  - content/docs/
    - index.mdx 랜딩 — 어느 topic에도 안 속한다
    - server/
      - **_deck.mjs** 덱 metadata · 그룹 · DeckMap
      - **_baseline.md** 기준 버전 · 덱 규칙 — 빌드에서 제외
      - **index.mdx** 덱 개요 — /server/ 가 된다
      - 00-intro.mdx 그룹 · 순서를 가진 본문 → /server/00-intro/
      - 01-shell.mdx …
    - starlight/ 이 덱
  - components/ 역할별 `layout/` · `docs/` · `demos/` (6장)
  - styles/custom.css 사이트 전역 조정
- docs/ 레포 운영 문서 — 사이트에는 안 나온다
</FileTree>

규칙은 네 줄이면 끝난다 —

- 경로가 slug다: `starlight/03-starlight.mdx` → `/starlight/03-starlight/`
- 폴더의 `index.mdx`가 그 폴더 URL(`/starlight/`)이 된다 — 덱 개요 페이지의 자리
- `_deck.mjs`가 있는 폴더가 덱이다. `_` 파일은 콘텐츠 컬렉션 밖이라 검색·URL에는 나오지 않는다
- 본문 MDX의 `deckGroup`과 `sidebar.order`가 그 장의 소속과 순서를 정한다

:::caution[함정]
덱 폴더에 본문을 만들 때 `deckGroup`이나 `sidebar.order`를 빼면 loader가 명시적으로 실패한다.
그 둘을 적으면 중앙 목록 수정 없이 topic에 자동 등록된다. 덱 밖에 만드는 페이지는 여전히
topics 플러그인의 `exclude`에 넣어야 한다 — 현재는 랜딩(`/`) 하나다.
:::

## 프론트매터 — 내용 두 필드, 구조 두 필드

```mdx
---
title: "3. Starlight의 구조"
description: "파일이 곧 페이지가 되는 라우팅, slug, ..."
deckGroup: astro
sidebar:
  order: 40
---
```

Starlight의 프론트매터 스키마에는 필드가 많다 — `sidebar`(순서·라벨·배지), `template: splash`,
`hero`, `banner`, `lastUpdated` 등. 이 레포의 본문은 내용 두 필드와 탐색 구조 두 필드만 필수로 쓴다.

- `deckGroup`은 같은 폴더 `_deck.mjs`의 `groups[].id`를 가리킨다
- `sidebar.order`는 덱 전체에서 유일한 숫자다. 중간 삽입을 위해 보통 10 단위로 둔다
- 사이드바 라벨은 `title`에서 온다 — 장 번호를 제목에 유지하는 이유다 ("3. Starlight의 구조")
- `description`은 검색 결과·SEO·링크 미리보기에 쓰인다 — **비워 두지 않는다**(7장)

`aliases`·`reviewedAt`·`status` 같은 검색·현재성 필드는 필요할 때만 더한다. 덱 `index.mdx`에는
그룹·순서가 필요 없고, 덱 별칭은 `_deck.mjs`에 둔다. 랜딩(`src/content/docs/index.mdx`)은
`template: splash`와 `hero`까지 쓰는 별도 표지다.

## 사이드바 — 이 레포는 topics로 쪼갠다

기본 Starlight의 사이드바는 사이트 전체에 한 벌이다. 주제 하나짜리 문서(대부분의 제품 문서)에는
그걸로 충분하지만, 이 사이트는 **서로 무관한 덱 여러 개**를 담는다 — CKA와 Kafka가
한 사이드바에 늘어서면 스크롤 지옥이 된다. 그래서 starlight-sidebar-topics 플러그인으로
덱마다 독립 사이드바를 준다.

```js
// src/content/docs/starlight/_deck.mjs — 덱이 소유하는 정보
export default {
  navOrder: 1300,
  catalogOrder: 2000,
  label: 'Starlight',
  // ...title · icon · category · tags · termIntro...
  groups: [
    { id: 'intro', label: '시작' },
    { id: 'astro', label: '기반' },
  ],
  map: [/* index의 DeckMap 단계 */],
}

// astro.config.mjs — loader가 만든 최종 topics만 연결한다
starlightSidebarTopics(topics, { exclude: ['/'] })
```

`load-decks.mjs`는 `_deck.mjs`가 있는 폴더를 모두 찾고, 각 본문을 `deckGroup`으로 묶은 뒤
`sidebar.order`로 정렬한다. 같은 데이터에서 랜딩 카드와 장 수를 만들고, index의
`<DeckMap deck="starlight" />`도 `_deck.mjs`의 `map`을 읽는다. **한 사실의 편집 지점이 그 사실을
가장 잘 아는 파일 하나**에 남는 구조다.

여기서 깨지기 쉬운 지점 셋 —

- `deckGroup`은 실제 group id여야 하고 `sidebar.order`는 덱 안에서 겹치면 안 된다 — loader가 잡는다
- 파일명을 바꾸면 본문과 `_deck.mjs`의 `map` 링크를 확인한다 — 렌더된 내부 링크 검사가 잡는다
- topic 밖 페이지는 `exclude`에 넣어야 경고가 안 난다 — 현재는 랜딩(`/`) 하나다

## 이 레포가 기본값에서 바꾼 것들

기본 Starlight와 이 사이트의 차이 — 전체 목록은
[docs/starlight-changes.md](https://github.com/mechurak/study-starlight/blob/main/docs/starlight-changes.md)에 있고, 굵은 것만 추리면 —

| 바꾼 것 | 수단 | 층 |
|---|---|---|
| 덱별 사이드바 | starlight-sidebar-topics **플러그인** | Starlight |
| 덱 데이터 자동 파생 | `_deck.mjs` + MDX를 읽는 loader | 프로젝트 |
| 외관 테마 | starlight-theme-rapide **플러그인** | Starlight |
| D2 렌더 (다이어그램) | astro-d2 **integration** (starlight보다 먼저!) | Astro |
| 이미지 확대 | starlight-image-zoom **플러그인** | Starlight |
| 본문 폰트 | Pretendard 셀프호스팅, `customCss` | CSS |
| 사이드바 UI (드롭다운·접기) | 컴포넌트 **override** — `Sidebar` · `SiteTitle` (6장) | Starlight |
| 검색 결과에 덱 이름 | `MarkdownContent` override로 Pagefind meta 주입 | Starlight |

수단의 층을 구분한다 — **plugin은 Starlight에, integration은 Astro에, 파생 loader는 프로젝트
데이터 층에, CSS는 표현 층에** 있다. 문제가 생겼을 때 어느 문서를 뒤질지가 이 구분에서 나온다.

## 3장 요약

- Starlight는 라우팅·탐색·검색·다크모드·i18n·SEO를 **전부 내장**한다 — 우리 몫은 콘텐츠와 구조 선언뿐
- **파일 경로 = slug = URL.** 폴더의 `index.mdx`가 덱 개요, `_` 파일은 빌드 밖
- 본문 프론트매터는 **title · description · deckGroup · sidebar.order** — 페이지가 자기 소속과 순서를 가진다
- 이 레포는 topics 플러그인으로 **덱마다 독립 사이드바** — loader가 덱별 설정과 페이지를 합성한다
- 확장 수단은 층을 구분한다 — Starlight plugin / Astro integration / project loader / CSS·override
