## 대시보드에서 저장소를 가져온다

[Astro 공식 Vercel 안내](https://docs.astro.build/en/guides/deploy/vercel/)대로 정적 사이트에는
어댑터가 필요 없다. 이 저장소에는 `@astrojs/vercel`을 넣지 않는다.

<Steps>

1. [Vercel 대시보드](https://vercel.com/new)에서 **Add New → Project**를 고르고 GitHub 저장소를 선택한다.

2. Framework Preset이 **Astro**로 감지되는지 본다. 빌드 명령과 출력 디렉터리 `dist`는 프리셋이 채운다.

3. **Deploy**를 누른다. 끝나면 `<프로젝트>.vercel.app` 주소가 생기고, 이후 `main` 푸시는 프로덕션,
   다른 브랜치 푸시는 Preview로 배포된다.

</Steps>

## 패키지 관리자와 Node 버전은 자동 감지에 맡긴다

[Vercel 문서](https://vercel.com/docs/package-managers)에 따르면 Vercel은 저장소의 lockfile을
보고 패키지 관리자를 고른다. 이 저장소에는 `package-lock.json`이 있으므로 `npm install`을 쓴다.
npm은 sharp·esbuild 같은 의존성의 설치 스크립트를 기본으로 실행하므로 별도 허용 설정도 없다.

Node 버전도 손대지 않는다. `package.json`의 `engines.node`가 `>=24`이고,
Vercel은 이 범위를 최신 24.x로 해석한다.

## 랜딩의 수정일이 어긋날 수 있다

Vercel 빌드는 저장소를 `--depth=10`으로 얕게 복제한다. 랜딩 카드의 "마지막 수정"은 각 덱 폴더의
최신 커밋일을 git log에서 읽으므로, 최근 10개 커밋 안에서 안 바뀐 덱은 모두 같은 경계 날짜로 표시된다.

저장소의 `scripts/prepare-git-history.mjs`는 `CF_PAGES=1`일 때만 전체 이력을 받는다.
Vercel에서도 같은 처리를 하려면 그 스크립트가 `VERCEL=1`도 인식하도록 고쳐야 하고, 이 변경은
아직 하지 않았다. 수정일 표시가 중요하지 않다면 그대로 둬도 사이트는 정상 동작한다.

## 주소와 site를 맞춘다

프로젝트 **Settings → Domains**에서 커스텀 도메인을 붙일 수 있다. 어느 주소를 대표로 쓰든
`astro.config.mjs`의 `site`를 그 주소로 바꿔야 canonical과 sitemap이 맞는다.

```js title="astro.config.mjs"
export default defineConfig({
  site: 'https://<프로젝트>.vercel.app', // 커스텀 도메인을 붙였다면 그 주소
});
```

배포 뒤 확인은 GitHub Pages와 같다.

```bash
curl -s https://<프로젝트>.vercel.app/starlight/intro/ | grep -o '<link rel="canonical"[^>]*>'
```

## CLI로 올리고 싶을 때

대시보드 연동 없이도 저장소 루트에서 다음 한 번이면 된다. 설치 방법은
[Vercel CLI 문서](https://vercel.com/docs/cli)를 따르고 본문에 복사하지 않는다.

```bash
vercel
```

프레임워크 설정을 덮어쓸지 물으면 아니오를 고른다. 이 방식은 로컬 파일을 올리므로 Git 이력
문제는 없지만, 푸시할 때마다 자동 배포되는 것은 아니다.

## 확인할 제한

- lockfile 기반 npm 감지는 2026-09-18 공식 문서로 확인했고 실제 Vercel 배포로 실측하지 않았다.
  첫 빌드 로그에서 설치 단계가 `npm install`인지 본다.
- 비공개 저장소는 조직 소유일 때 요금제 제한이 있다. 개인 계정의 비공개 저장소는 Hobby로도 된다.
- Preview 배포는 기본으로 검색엔진 색인에서 제외된다. 프로덕션 주소만 `site`에 넣는다.

## 이해 확인

배포는 성공했는데 랜딩의 거의 모든 덱이 최근 날짜 하나로 뭉쳐 보인다. 무엇부터 볼까?
얕은 복제가 원인이다. depth 10 안에서 안 바뀐 덱은 경계 날짜로 뭉개진다. 이건 빌드 실패가
아니라 표시 문제이므로, 수정일이 중요하면 위의 스크립트 변경을 먼저 해야 한다.
