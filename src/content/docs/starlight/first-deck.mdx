확인한다. 이 예제는 학습용 `sample-notes` 폴더만 추가하며 기존 덱을 고치지 않는다.
같은 이름의 폴더가 이미 있으면 덮어쓰지 말고 다른 이름을 고른 뒤 아래 경로·링크·deck 값을 함께 바꾼다.

## 네 파일은 서로 다른 질문에 답한다

| 파일 | 답하는 질문 |
|---|---|
| `_baseline.md` | 누구에게 무엇을 어느 범위까지 설명하는가 |
| `_deck.mjs` | 어떤 덱이며 페이지를 어떤 그룹·순서로 읽는가 |
| `index.mdx` | 왜 읽고 어디서 시작하는가 |
| `page-order.mdx` | 페이지 순서를 어떻게 바꾸는가 |

다음 파일을 표시한 경로에 만든다. `navOrder`·`catalogOrder` 9000을 쓰는 덱이 있다면 다른 값을
고른다. category `tools`와 tag `frontend`는 `src/data/catalog.mjs`의 기존 어휘를 재사용한다.
새 어휘가 필요할 때만 catalog를 고치고 사용하지 않는 태그를 미리 추가하지 않는다.

## 학습 범위를 baseline에 적는다

```md title="src/content/docs/sample-notes/_baseline.md"
# 페이지 순서 연습의 기준

독자: Markdown과 파일 편집을 아는 사이트 작성자.
선행 지식: MDX frontmatter, 저장소에서 명령 실행.
학습 결과: 페이지 이름과 읽는 순서를 분리하고 기존 URL을 유지하며 순서를 바꾼다.
범위: 이 저장소의 덱 loader와 sidebar 배열. 라우터 커스터마이즈는 다루지 않는다.
기준: 현재 저장소의 load-decks.mjs와 content-authoring.md.
서술 규칙: 이름·URL에는 순서 번호를 넣지 않고 예제의 관찰 결과를 설명한다.
```

## 덱 설정을 만든다

```js title="src/content/docs/sample-notes/_deck.mjs"
export default {
  navOrder: 9000,
  catalogOrder: 9000,
  label: '페이지 순서 연습',
  title: '페이지 순서 연습',
  description: '페이지 주소와 읽는 순서를 나누는 작은 실습',
  icon: 'document',
  category: 'tools',
  tags: ['frontend'],
  termIntro: 'required',
  sidebar: [{ label: '기본', pages: ['page-order'] }],
  map: [{
    label: '적용',
    title: '페이지 순서',
    href: '/sample-notes/page-order/',
    desc: '주소를 유지하면서 목록 순서 바꾸기',
    tone: 'key',
  }],
};
```

이 파일이 있으면 loader가 폴더를 덱으로 발견한다. `page-order.mdx`는 `pages`에 적힌 위치에
들어가며 구성도는 `map`의 현재 페이지 링크를 사용한다. `index.mdx`는 목록에 적지 않고,
사이트 전체의 중앙 덱 목록도 따로 추가하지 않는다.

## 주소와 순서를 나눈다

이 파일의 주소는 `/sample-notes/page-order/`다. 덱 설정의 pages 목록에서 위치를 옮겨도
파일명이 같으면 주소는 유지된다. 본문이 하나뿐이면 앞뒤 순서 변화를 볼 수 없으므로
아래에서는 둘째 페이지를 만들어 확인한다.

## 적용하고 확인한다

1. 이 파일을 같은 폴더의 `practice.mdx`로 복사하고, title을 `순서 확인`, description을
   `두 페이지의 목록 위치를 바꾸어 순서와 주소를 확인한다`로 고친다. 나머지 본문·컴포넌트는 유지한다.
2. `_deck.mjs`의 pages를 `['page-order', 'practice']`로 바꾼다.
3. 두 이름의 위치를 바꾸어 `['practice', 'page-order']`로 저장하고 저장소 루트에서
   `npm run check`를 실행한다.
4. 예상 결과는 검사 통과와 기본 그룹의 `순서 확인 → 페이지 순서` 순서다.
   `/sample-notes/page-order/` 주소는 유지된다. 실행 중 dev 서버는 재시작한다.
5. 실습 후 pages를 `['page-order']`로 되돌리고 이번에 복사한 `practice.mdx`만 제거한다.
   최종 상태에서 `npm run check`를 실행해 원래 목차로 돌아왔는지 확인한다.

## 검증하고 결과를 읽는다

저장소 루트에서 실행한다.

```bash
npm run check
node --input-type=module -e "import { topicPageSlugs } from './src/data/decks.mjs'; console.log(topicPageSlugs.filter(s => s.startsWith('sample-notes')))"
```

예상 결과는 검사 성공과 `sample-notes`, `sample-notes/page-order` 두 slug다.
`dist/sample-notes/index.html`과 `dist/sample-notes/page-order/index.html`이 생성되고,
덱 메뉴·랜딩 데이터·사이드바가 같은 원본에서 파생된다. 구성도 링크는 `_deck.mjs`의 map을 따른다.
실행 중 dev 서버가 있다면 재시작해야 새 덱 설정을 읽는다.

| 실패 | 볼 곳 |
|---|---|
| 덱이 발견되지 않음 | 폴더의 `_deck.mjs`, ASCII 소문자 slug |
| 페이지 누락·중복 | sidebar의 pages 목록에 각 본문이 정확히 한 번 있는지 |
| 없는 파일·빈 그룹 | pages의 이름과 실제 MDX, 그룹별 페이지 목록 |
| 필수 컴포넌트 누락 | index의 LinkButton·DeckMap, 본문의 Thesis·TermIntro |
| 구성도 링크 실패 | map의 href와 실제 파일 경로 |

자동 성공 뒤에도 예제의 원리·관찰·답이 연결되는지 읽는다. 위 본문의 순서 변경 연습은
둘째 페이지가 있어야 변화를 볼 수 있고, 파일명은 유지하므로 기존 URL도 유지된다.

## 실습 파일을 복구한다

계속 쓸 덱이라면 이름·독자·주제·근거를 실제 목적에 맞게 고친다. 연습만 했다면 이번에 만든
`src/content/docs/sample-notes/` 네 파일과 폴더를 제거한다. 순서 연습 중 만든 `practice.mdx`가
남아 있으면 함께 제거한다. 기존 폴더를 수정했다면 전체를 지우지
말고 이번 변경만 복구한다. 제거도 사이트 결과를 바꾸므로 최종 상태에서 `npm run check`를 실행한다.
