[시작하기](/starlight/intro/)의 설치를 마친 저장소에서 **작은 덱을 만들고 무엇이 자동으로 등록되는지**
확인한다. 이 예제는 학습용 `sample-notes` 폴더만 추가하며 기존 덱을 고치지 않는다.
같은 이름의 폴더가 이미 있으면 덮어쓰지 말고 다른 이름을 고른 뒤 아래 경로·링크·deck 값을 함께 바꾼다.

]} />

## 네 파일은 서로 다른 질문에 답한다

| 파일 | 답하는 질문 |
|---|---|
| `_baseline.md` | 누구에게 무엇을 어느 범위까지 설명하는가 |
| `_deck.mjs` | 어떤 덱이며 어떤 그룹으로 묶는가 |
| `index.mdx` | 왜 읽고 어디서 시작하는가 |
| `page-order.mdx` | 페이지 순서를 어떻게 바꾸는가 |

다음 파일을 표시한 경로에 만든다. `navOrder`·`catalogOrder` 9000을 쓰는 덱이 있다면 다른 값을
고른다. category `tools`와 tag `frontend`는 `src/data/catalog.mjs`의 기존 어휘를 재사용한다.
새 어휘가 필요할 때만 catalog를 고치고 사용하지 않는 태그를 미리 추가하지 않는다.

## 학습 범위를 baseline에 적는다

```md title="src/content/docs/sample-notes/_baseline.md"
# 페이지 순서 연습의 기준

독자: Markdown과 파일 편집을 아는 사이트 작성자.
선행 지식: MDX frontmatter, 저장소에서 명령 실행.
학습 결과: 페이지 이름과 읽는 순서를 분리하고 기존 URL을 유지하며 순서를 바꾼다.
범위: 이 저장소의 덱 loader와 sidebar.order. 라우터 커스터마이즈는 다루지 않는다.
기준: 현재 저장소의 load-decks.mjs와 content-authoring.md.
서술 규칙: 이름·URL에는 순서 번호를 넣지 않고 예제의 관찰 결과를 설명한다.
```

## 덱 설정을 만든다

```js title="src/content/docs/sample-notes/_deck.mjs"
export default {
  navOrder: 9000,
  catalogOrder: 9000,
  label: '페이지 순서 연습',
  title: '페이지 순서 연습',
  description: '페이지 주소와 읽는 순서를 나누는 작은 실습',
  icon: 'document',
  category: 'tools',
  tags: ['frontend'],
  termIntro: 'required',
  groups: [{ id: 'basics', label: '기본' }],
  map: [{
    label: '적용',
    title: '페이지 순서',
    href: '/sample-notes/page-order/',
    desc: '주소를 유지하면서 정렬값 바꾸기',
    tone: 'key',
  }],
};
```

이 파일이 있으면 loader가 폴더를 덱으로 발견한다. 본문 그룹은 `basics`로 연결하고 구성도는
`map`의 현재 페이지 링크를 사용한다. 중앙 덱 목록을 따로 추가하지 않는다.

## 주소와 순서를 나눈다

이 파일의 주소는 `/sample-notes/page-order/`다. frontmatter의 order를 10에서 20으로 바꿔도
파일명은 그대로이므로 주소는 유지된다. 본문이 하나뿐이면 화면 순서는 그대로 보인다.
둘째 페이지가 order 15로 같은 그룹에 있으면 10일 때는 그 앞, 20일 때는 그 뒤에 놓인다.

## 적용하고 확인한다

이 파일의 order만 20으로 바꾸고 저장소 루트에서 `pnpm check`를 실행한다.
예상 결과는 검사 통과와 같은 페이지 URL이다. 실습 후 order를 10으로 되돌린다.
다른 페이지와 정렬값이 겹치면 loader가 실패하므로 덱 안에서 유일한 값을 쓴다.

## 검증하고 결과를 읽는다

저장소 루트에서 실행한다.

```bash
pnpm check
node --input-type=module -e "import { topicPageSlugs } from './src/data/decks.mjs'; console.log(topicPageSlugs.filter(s => s.startsWith('sample-notes')))"
```

예상 결과는 검사 성공과 `sample-notes`, `sample-notes/page-order` 두 slug다.
`dist/sample-notes/index.html`과 `dist/sample-notes/page-order/index.html`이 생성되고,
덱 메뉴·랜딩 데이터·사이드바·장 수가 같은 원본에서 파생된다. 구성도 링크는 `_deck.mjs`의 map을 따른다.
실행 중 dev 서버가 있다면 재시작해야 새 덱 설정을 읽는다.

| 실패 | 볼 곳 |
|---|---|
| 덱이 발견되지 않음 | 폴더의 `_deck.mjs`, ASCII 소문자 slug |
| 그룹 오류 | 본문의 deckGroup과 groups id 일치 여부 |
| 순서 중복 | 덱 전체 본문의 sidebar.order |
| 필수 컴포넌트 누락 | index의 LinkButton·DeckMap, 본문의 Thesis·TermIntro |
| 구성도 링크 실패 | map의 href와 실제 파일 경로 |

자동 성공 뒤에도 예제의 원리·관찰·답이 연결되는지 읽는다. 위 본문에서 페이지 하나만으로는
앞뒤 순서 변화를 눈으로 볼 수 없다는 제한을 숨기지 않는 것도 의미 리뷰다.

## 실습 파일을 복구한다

계속 쓸 덱이라면 이름·독자·주제·근거를 실제 목적에 맞게 고친다. 연습만 했다면 이번에 만든
`src/content/docs/sample-notes/` 네 파일과 폴더를 제거한다. 기존 폴더를 수정했다면 전체를 지우지
말고 이번 변경만 복구한다. 제거도 사이트 결과를 바꾸므로 최종 상태에서 `pnpm check`를 실행한다.
