## 전체를 관통하는 두 문장

**콘텐츠 · 구조 · 표현은 다른 층이다.** 글은 `src/content/docs/`의 마크다운,
덱 설정은 각 폴더의 `_deck.mjs`와 페이지 frontmatter, 전역 어휘는 `src/data/catalog.mjs`,
사이트 설정은 `astro.config.mjs`, 시각 패턴은 `src/components/` — 층이 분리되어 있어서
글을 고치다 사이트 구조를 깨뜨릴 가능성을 줄이고, 구조를 바꿔도 본문은 그대로 남는다.
무언가 이상하면 "어느 층인가"부터 묻는다.

**의미 리뷰와 기술 검증은 다른 일이다.** 자동 검사는 MDX·D2 문법과 렌더된 내부 링크를
확인한다. 설명의 정확성과 적용 가능성은 근거·예제·이해 확인으로 검토한다.
추가 화면 확인은 변경한 동작에 필요할 때만 한다.

## 작업부터 시작하는 경로

Git·Markdown·기본 명령 실행을 아는 독자라면 [시작하기](/starlight/intro/)에서 환경을 준비하고,
[첫 덱 작성](/starlight/first-deck/) → [문서 작성](/starlight/writing/) →
[빌드와 검증](/starlight/pipeline/) 순서로 진행한다. 완성 뒤 덱·페이지를 직접 추가하고
검사 결과를 해석할 수 있는 것이 목표다. Astro·구조·컴포넌트 페이지는 필요할 때 참조한다.
일반 웹앱 개발과 특정 호스팅의 전체 운영은 다루지 않는다.
