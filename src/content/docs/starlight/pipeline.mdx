## pnpm build가 하는 일

이 사이트는 Astro가 MDX와 컴포넌트를 정적 HTML로 만들고 Starlight가 Pagefind 인덱스를 만든다.
산출물은 `dist/`다. `pnpm preview`는 이 산출물을 로컬에서 확인하는 명령이며 배포는 아니다.

`pnpm build`에는 `prebuild`가 있어 선택 배포 환경의 얕은 Git 이력을 준비한다.
`pnpm check`는 콘텐츠 검사 → `astro build` → 렌더된 내부 링크 검사로 실행된다.
명령 이름은 비슷해도 `package.json`에 정의된 단계가 다르므로 필요한 진입점을 쓴다.

## dev와 최종 검사는 다른 물건이다

| 확인할 것 | 명령 |
|---|---|
| 편집 중 페이지 | `pnpm astro dev --background` |
| dev 상태·로그·종료 | `pnpm astro dev status` · `logs` · `stop` |
| 최종 콘텐츠·빌드·내부 링크 | `pnpm check` |
| 빌드 결과 확인 | `pnpm preview` |

dev 서버는 선택 사항이다. 페이지를 추가·이름 변경한 뒤 dev를 계속 쓴다면 서버를 재시작해
config에서 파생한 사이드바를 다시 읽는다. 일반 `pnpm dev`는 포그라운드 실행이다.
`astro`는 로컬 의존성이므로 이 저장소에서는 `pnpm`을 거쳐 호출한다.

## 빌드가 잡는 것, 못 잡는 것

| 판정 대상 | 확인 수단 |
|---|---|
| 필수 metadata·그룹·순서·baseline | check:content와 loader |
| MDX 문법·import·D2 생성 | Astro 빌드 |
| 렌더된 내부 페이지·파일·절 링크 | check:links |
| TypeScript 타입 | 일반 build와 별개. 이 프로젝트 check가 타입 검사를 포함한다고 가정하지 않음 |
| 주장 정확성·예제의 학습 목적 | 의미 리뷰·근거 대조·예제 실행 |
| 바뀐 화면 동작 | 필요한 대표 페이지의 브라우저 확인 |

### 변경별 최소 검증

- 사이트 본문·코드·설정 변경은 작업 묶음의 끝에 `pnpm check`를 실행한다.
- 빌드 밖 지침·계획만 바꾸면 diff와 참조 경로를 확인한다.
- 페이지 추가·분할·순서 변경은 자동 검사와 metadata 대조로 마친다.
- 새 이미지·D2 배치는 정적 렌더로 확인한다. 일반 표나 기존 컴포넌트 사용만으로 화면 검사를 늘리지 않는다.
- CSS·UI·클라이언트 이동 동작을 바꾸면 해당 동작을 대표 페이지 1~2개에서 확인한다.

Tabs 안의 동작을 확인하려면 실제 탭을 선택한다. 숨긴 패널을 모두 강제로 열거나 전체 덱을
순회하지 않는다. 검사가 통과하면 끝내고, 새 변경·실패·미해결 문제가 있을 때만 반복한다.
정본은 `docs/verification.md`다.

## 검색 — Pagefind의 동작

[Starlight 검색](https://starlight.astro.build/guides/site-search/)은 빌드 결과의 본문을 색인한다.
이 프로젝트는 `MarkdownContent.astro`에서 덱 이름과 aliases를 HTML에 추가한다.
검색 결과의 발췌는 질의와 색인된 본문에 따라 달라지며 description과 동일한 줄로 고정되지 않는다.

| 설정·파일 | 의미 |
|---|---|
| `_baseline.md` | 본문 컬렉션에서 제외되어 페이지가 없음 |
| topic plugin의 `exclude` | topic 소속에서 제외. 페이지·검색을 없애는 설정 아님 |
| frontmatter의 `pagefind: false` | 해당 페이지를 검색 색인에서 제외 |
| `data-pagefind-ignore` | 페이지 안 특정 영역을 검색에서 제외 |

따라서 랜딩이 topic 밖이라고 HTML이 없다고 설명하면 틀린다.
검색에 새 내용이 없다면 최신 빌드·배포 여부와 검색 제외 설정을 먼저 확인한다.

## 배포 전에 결정할 것

이 페이지의 로컬 검사에는 외부 배포가 필요 없다. 원본 저장소의 기존 Cloudflare Pages 운영 값은
`docs/deploy.md`에 있고, 새로운 사이트는 배포 대상을 정한 뒤 그 환경에 맞춰 설정한다.

| 값 | 편집·확인 위치 |
|---|---|
| 대표 주소 | `astro.config.mjs`의 site |
| 사이트 제목·언어 | 같은 파일의 starlight 설정 |
| 빌드 명령·출력 | package scripts와 호스팅 설정의 dist |
| Node·pnpm | .nvmrc·package.json의 고정 조건 |
| 네이티브 도구 | D2 최초 다운로드와 esbuild·sharp 빌드 허용 |

canonical은 검색엔진에 대표 주소를 알리는 신호이며 방문자를 이동시키거나 검색엔진의 선택을
보장하지 않는다. 다른 사이트로 복사할 때 원본 site 값을 그대로 발행하지 않는다.

### Cloudflare Pages가 아니라면

정적 산출물을 제공할 호스팅이어도 base path·빌드 환경·대표 주소·배포 방식은 별도 확인한다.
현재 본문 링크는 `/starlight/intro/` 같은 루트 기준이다. `/repo/` 하위 경로 배포를 한다고
Astro base만 설정하면 모든 본문 링크가 자동으로 바뀌는 것은 아니다.
기본 안내는 도메인 루트 배포를 전제로 하며, 하위 경로 지원은 본문·공용 컴포넌트·검사까지
함께 고쳐 실제 링크를 확인해야 한다. 가상의 rehype 코드 한 줄로 해결됐다고 취급하지 않는다.

## 이해 확인

새 페이지를 topic에서 제외하면 검색에서도 사라질까? 아니다. topic 소속과 Pagefind 색인 설정은
서로 다른 역할이다. 검색 제외가 목적이면 해당 설정과 빌드 결과를 확인해야 한다.
