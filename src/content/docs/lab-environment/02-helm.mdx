Docker·kind·kubectl은 [kind 실습 환경](/lab-environment/01-kind/)에서 먼저 준비한다. Helm은 여러 기술 덱이
chart 설치에 공통으로 쓰므로 개별 실습에서 반복하지 않고 이 장에서 한 번 준비한다.

## 전체에서 Helm의 자리

```text
로컬 helm CLI ── chart + values ──▶ Kubernetes API ──▶ release resource
```

Helm CLI는 현재 `kubectl`과 같은 kubeconfig·context를 사용한다. 그래서 설치 확인은 `helm version`만으로
끝나지 않는다. 명령을 실행할 cluster가 맞는지 먼저 확인해야 한다.

## 공식 문서에서 설치하기

설치 명령이나 installer script는 이 문서에 복제하지 않는다. Helm 공식 설치 페이지에서 현재 major와
운영체제별 방법을 확인하고, 선택한 방법의 안내를 그대로 따른다.

<TabItem label="macOS">

**From Homebrew (macOS)** 또는 공식 binary 경로를 선택해 설치한다. Homebrew formula는 Helm project가
아니라 Homebrew community가 유지한다는 문서의 경계도 함께 확인한다.

</TabItem>
<TabItem label="Ubuntu">

<ExternalLink href="https://helm.sh/docs/intro/install/">Helm 공식 문서 — Installing Helm</ExternalLink>에서
공식 binary·installer 또는 **From Apt (Debian/Ubuntu)** 중 환경 정책에 맞는 경로를 선택한다. 오래된 글의
installer 이름이나 URL을 복사하지 말고, 실행 시점에 공식 페이지가 안내하는 현재 major를 따른다.

설치가 끝나면 terminal을 새로 열고 CLI가 실행되는지 확인한다.

```bash
helm version
```

## kind cluster와 연결 확인

Helm 자체 설치와 cluster 대상 확인을 분리한다. `study` cluster를 사용하는 경우 다음 순서로 본다.

```bash
kind get clusters
kubectl config current-context
kubectl --context kind-study get nodes
helm --kube-context kind-study list --all-namespaces
```

마지막 명령이 빈 표를 보여도 정상이다. 아직 release가 없다는 뜻이지 Helm이 연결되지 않았다는 뜻이 아니다.
TLS·인증·권한 오류가 나오면 Helm을 다시 설치하지 말고 같은 context의 `kubectl` 연결부터 고친다.

## 설치와 release를 구분하기

| 확인 | 의미 |
|---|---|
| `helm version` | host에 Helm CLI가 있고 실행된다 |
| `helm --kube-context … list -A` | 지정한 cluster API에 접속하고 release를 읽을 수 있다 |
| `helm install` | chart를 cluster에 새 release로 만든다 |
| `helm upgrade` | 기존 release의 chart·values revision을 바꾼다 |
| `helm uninstall` | 지정한 release resource를 cluster에서 제거한다 |

Helm CLI를 host에서 지우는 것과 `helm uninstall`로 cluster release를 지우는 것은 전혀 다른 cleanup이다.

## 안 될 때 먼저 볼 것

| 증상 | 확인 |
|---|---|
| `helm: command not found` | 설치 위치가 `PATH`에 있는지, terminal을 다시 열었는지 |
| installer가 checksum 단계에서 중단 | 검증을 끄지 말고 다운로드를 지운 뒤 네트워크·공식 release 상태 확인 |
| cluster connection refused | `kubectl --context <이름> cluster-info`부터 확인 |
| release list 권한 거부 | kubeconfig user와 해당 namespace의 Kubernetes RBAC 확인 |
| 엉뚱한 cluster의 release가 보임 | 모든 실습 명령에 `--kube-context`를 명시 |

## 업데이트할 때

Helm major가 바뀌면 chart 호환성과 plugin을 확인한다. 무조건 최신으로 올리기 전에 해당 실습이 요구하는 Helm
version과 [version skew 정책](https://helm.sh/docs/topics/version_skew/)을 확인하고 `helm version` 출력을 기록한다.
